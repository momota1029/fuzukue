## できた条件

- 友人が自分のサーバーの通常の受付で「この不具合を fuzukue に送って」と頼むと、組み込みの既定宛先「fuzukue プロジェクト」（公開リポジトリ `momota1029/fuzukue`）への下書きが出る。送り先と内容を利用者が確認してから、友人自身の GitHub アカウントで一般の外部コントリビューターとして Issue または fork からの PR を作る。
- 受信側で既存の Issue・PR 受付に届く。公開の返信や結果を友人の元のスレッドに短く表示する。送信元と受信側の会話、資料、作業ログはそれぞれのワークスペースに残る。

- 利用者が公開を選んだとき、公開先、題名、本文、コードブロックと入出力例、作者と許可を表示し、確認後に既存の起票経路で出せる。非公開の会話、添付、パス、ルーティング情報は投稿に含まれない。公開後の Issue と成果の PR を元のスレッドからたどれる。
- 短いコードは Issue に置ける。複数ファイルには利用者が選んだ公開用 Gist の固定版や fork のコミットをリンクでき、実装の差分は PR として紐づけられる。返事の本文は公開前に確認でき、採用した方法と利用可能な版が分かる。
- Issue の作成が成功したあとに紐づけに失敗しても、作成済み URL から再開できる。同じ起票を重ねず、非公開の添付を代替経路へ送らない。
