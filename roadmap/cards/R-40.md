## できた条件

- 承認後に同じ判断が遅れて届く場合や再送される場合を再現する。判断は一度だけ適用し、後続の重複で会話に `error` を追加しない。
- 許可・拒否の双方で回帰テストを通す。実在しない依頼 ID にはエラーを返し、先に確定した判断は変えない。

## 根拠

利用時のタイムラインでは、`approval_resolved` の直後に `unknown approval request` の `error` が 24 件連続した。

サーバーは、タイムラインから復元したものを含め、解決済みの承認 ID を保持する。`Resolve` が再送されても最初の判断を維持し、`approval_resolved` や `error` を追加しない。未発行の ID には `unknown approval request` を返す。 [承認の記録](../../crates/secretaire/src/hub.rs) · [承認の受付](../../crates/secretaire/src/main.rs)

## 検証

修正前の `1719fb0` では、許可・拒否の再送がどちらも `unknown approval request` になり、委譲の接頭辞を持つ未発行 ID が受理された。

`approval_resolution_retry_preserves_accept` と `approval_resolution_retry_preserves_decline` は、最初の判断がバックエンドに一度だけ届き、同じ判断や逆の判断を送っても追加の解決イベントやエラーが発生しないことを確認する。`approval_resolution_retry_rejects_unknown_ids` は、通常の ID に加え、委譲・Codex ワーカーの接頭辞を持つ未発行 ID が拒否されることを確認する。 [回帰テスト](../../crates/secretaire/src/delegate/approval.rs)

修正後の `cargo test -p secretaire --bin secretaire` は回帰テスト 3 件を含む 667 件が通過し、11 件が実行対象外だった。
