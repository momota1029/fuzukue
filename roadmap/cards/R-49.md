## できた条件

- GitHub 連携済みの受付と作業役が、シェルの承認なしでリポジトリの公開範囲、手元の HEAD の `cards.yml` の結果、指定タグのリリースとアセット、オープンの Issue を確認できる。
- PR、コミットと ref 間の比較、ファイル、ジョブとログ抜粋も読める。範囲外のリポジトリへのリクエストを止め、件数・ページ・バイトに上限を設ける。サーバーの資格情報は応答とエラーに含めない。
- GitHub のテスト用リポジトリで、公開・非公開の設定、権限不足、リリース資産、Actions の結果とログを確かめる。

## 根拠

リポジトリに範囲を絞った読み取り MCP と既存権限の一覧を追加した。`github_auth::read::tests` のモック HTTP で各ツール、許可範囲、出力の上限、資格情報の除去、キャッシュとレート制限を確認した。 [GitHub 連携](../../docs/github-auth.md)

2026-11-24、自己更新後に GitHub を再接続した環境で、作業役のセッションから読み取り MCP を確認した。受付が取得した自己更新の `status` では、`running_build_id` と `source_commit` がともに `3f2dd9a2c6e3fee84d8e87a41926b7261a6429b1`。作業役のチェックアウトの HEAD は `48153aec231909f3f9350bf94a27e38192b6fa80` だった。

- `github_repo({})` は成功し、作業リポジトリ `momota1029/fuzukue` の公開範囲を `public`、既定ブランチを `main` と返した。
- `github_repo({"repo":"octocat/Hello-World"})` は `isError: true` を返した。エラーは `GitHub repository is outside this workspace's read allowlist (github.issue_repos).`。
- `github_runs({"workflow":"cards.yml","ref":"48153aec231909f3f9350bf94a27e38192b6fa80","limit":1})` は `completed`、`success` の Cards 実行を返した。稼働版の完全 SHA を同じ方法で指定した呼び出しは `items: []` を返した。 [Cards 実行 45399032493](https://github.com/momota1029/fuzukue/actions/runs/45399032493)

テスト用リポジトリでの非公開設定、GitHub 側の権限不足、リリース資産、Actions のログの確認は残っている。
