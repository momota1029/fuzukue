## できた条件

- `fs_write`、`fs_edit`、`fs_apply_patch` の書き込み前と、シェルによる変更を含むジョブの完了・停止時の照合で、`touches` 範囲外の変更を同じ基準で判定する。
- 書き込み前の内容が `HEAD` と一致する Git 追跡済みファイル、`target/**` など Git で無視される再生成可能なビルド成果物、ジョブ専用の Git ワークツリーまたはクローン内でそのジョブが作ったファイルは、復元可能として扱う。事前承認なしで書き込みを許可し、`job_write_audit` で読める監査記録だけを残す。隔離コピーや要確認の警告は出さない。
- 未追跡の利用者データ、`HEAD` にない利用者のステージ済み・未ステージの変更、`inbox/`、`threads/`、`memos/`、非公開文書、リポジトリ外のファイルは保護する。復元を確かめられない変更には既存の承認・隔離を適用する。保護パスとリポジトリ外への書き込み拒否は、追跡の有無やジョブ専用の作業ツリー内かどうかにかかわらず維持する。
- `target/**` のビルド成果物は、数千ファイルの変更でも件数に集約して監査に残す。報告に表示する場合も件数だけを示し、パスごとの行や要確認の項目を作らない。

## 検証

一時リポジトリとジョブ専用ワークツリーを使い、書き込みツールでの承認の有無と、シェルによる変更を含む完了・停止時の監査、隔離コピー、報告を確かめる。`HEAD` と一致する追跡済みファイル、利用者のステージ済み・未ステージの変更がある追跡済みファイル、共有作業ツリーの未追跡データ、ジョブ専用ワークツリーの生成ファイル、保護パスとリポジトリ外を試す。`target/**` に数千ファイルを生成し、記録された件数が合い、報告がファイル数に応じて伸びないことを確かめる。
