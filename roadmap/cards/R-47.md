## できた条件

- MCP は判断が要る操作を永続キューに登録し、`pending` と承認 ID を即時に返す。利用者の応答がなくても独立作業を進めて部分成果を残す。同一操作は一件にまとまり、拒否・撤回・失効では実行が始まらない。
- デスクトップと Android の入力欄のすぐ上に承認ドックが固定される。スクロール中も判断でき、一括操作、再接続、両端末の判断の競合を検証する。判断済みの依頼は会話履歴へ移る。
- 範囲外の `fs_write`、フォルダー依頼、`git_commit_scoped` の範囲拡大が共通契約を使う。許可後に再検査して再試行でき、元ジョブが終了していても再起動をまたいで継続ジョブが一件だけ起動する。
- 夜間方針で自動実行・保留・利用者判断が必須の操作を区別する。予算と停止条件を強制し、朝に成果、未決の依頼、停止理由を報告する。
- シェルを含む基本操作を fuzukue MCP だけで完了できる。`exec` の実行・取り消し・出力上限、実環境での書き込みと通信の隔離を検証し、Claude と Codex の実務タスクを比較して役割ごとにネイティブ経路を廃止する。

`27038fb` で設計カードを追加した。操作の契約、端末間で揃える挙動、実装の順序と段階ごとの検証は設計カードに記録した。 [非同期承認と基本操作の MCP 化](../../cards/design/async-approvals.md)
