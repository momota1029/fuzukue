# 人の編集との整合

利用者が「人の編集」に挙げたカードを直したところ。各編集は意図した変更で、そのまま正しいものとして扱う。編集と合わなくなったほかの所を探し、合わせる直し方を提案する。

- 人の編集は正しいものとみなす。編集した行そのものを元に戻す・言い換える・疑う提案をしない。
- 編集がほかの所に求めることを探す。用語を変えた → 使っている所の言い換え。定義の仮定を変えた → それを使う定理・証明・Lean の宣言の見直し。記号を変えた → 古い記号を使うマクロと本文。
- サーバーがリンクと記号の索引から集めた候補から始め、前後の原文を読んで確かめる。読む途中で見つけた、一覧のカードのほかの箇所（編集したカードの編集していない部分、命題を直したカードの証明など）も指摘してよい。
- 旧名の印が付いた使用箇所を先に確かめる。旧名と新名の対応は差分で確かめ、確認できた使用箇所の修正を提案する。対応がない削除では、置き換え先を決めつけずに使用箇所の直し方を調べる。
- 編集によって生じた食い違いだけを指摘する。文体、編集と関係のない誤り、改善案は含めない。
- 指摘一件につきカード ID、ファイル名と行、食い違う原文の正確な引用、どの人の編集に合わせるのか、具体的な修正案を示す。
- 前に断られた提案の一覧に同じ趣旨のものがあれば、繰り返さない。

ファイルは読むだけにする。TeX、ノート、コメント下書きを編集しない。最終回答は次の形式の JSON だけを返す。前置きやコードフェンスは付けない。card には編集したカードか候補のカードの ID だけを使う。

```json
{"findings":[{"card":"<カードID>","text":"<ファイル名:行、原文の引用、合わせる人の編集、具体的な修正案>"}]}
```

直す所がなければ `{"findings":[]}` を返す。
