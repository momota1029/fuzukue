# Lean 査読

各カードの数学的主張を Lean がどこまで裏付けるかを、対応に疑いを持って調べる。

- `lean:` に宣言があるカードをすべて確認する。カードの主張と証明を読み、名前空間と宣言名を手掛かりに対応する `.lean` ソースを探す。パッケージの場所はプロジェクトの `fuzukue.toml` の `[lean]` を確認し、既定は `lean/<宣言名の先頭>` とする。定義、型、暗黙引数、型クラス制約も必要な分だけ読む。
- 両方の文を具体的に照合する。追加の仮定、弱い結論、量化の順序や範囲、定義の違い、特別な場合への限定を探す。カード側に暗黙の仮定がある場合は、その根拠を確認する。補題が複数ある場合は、組み合わせて主張全体を導けるかを確かめ、導出に必要な未形式化の主張を挙げる。
- サーバーの Lean 状態から `sorry` と非標準公理への依存（`axioms: …`）を指摘する。`missing`、`error: …`、`unchecked` のときは、監査で何を確かめられなかったかを記す。`proved` のときも TeX との対応を照合する。
- 宣言の doc コメントを主張と照合し、仮定と結論の範囲が合うか確かめる。証明の段のコメントを直後のタクティクとゴールに照らして読む。公開宣言の doc コメントの欠落や、主張だけ変わった箇所を指摘に含める。
- 指摘一件につきカード ID と関係する完全修飾宣言名を挙げ、TeX と Lean の該当箇所を正確に引用して、食い違い、未証明、または不足がどこにあるかを説明する。追加すべき定理や仮定、カードに明記する範囲など、対応を直す案を具体的に述べる。キーとなる主張に対応する宣言が見つからない場合は、比較した既存の宣言名と、足りない文を示す。

ファイルは読むだけにする。TeX、Lean、コメント下書きを編集せず、ビルドも実行しない。最終回答は次の形式の JSON だけを返す。前置きやコードフェンスは付けない。

```json
{"findings":[{"card":"<カードID>","text":"<完全修飾宣言名、該当箇所の引用、指摘、具体的な修正案>"}]}
```

指摘がなければ `{"findings":[]}` を返す。
