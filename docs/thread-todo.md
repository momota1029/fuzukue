# スレッドの TODO

スレッドごとに、頼まれたことと受付が約束したことを一覧に残します。メモは考えの置き場、TODO はやる約束です。目標（`plan.md`）とは別に保存するので、方針を立て直しても項目は残ります。

## 使い方

そのターンで終わらない依頼や「あとで」は、受付が確認を挟まずに項目にします。追加、修正、削除は会話で頼みます。受付は結果を確かめてから済みにし、根拠を項目の一言に残します。

デスクトップでは、項目のあるスレッドで入力欄の上の右側に「TODO 4 ・ 待ち 1」のように件数が出ます。件数は未完了（未着手、作業中、返事待ち、操作待ち）の数で、待ちは返事待ちと操作待ちの数です。押すと一覧が開きます。並びは作業中、待ち、未着手（古い順）で、済みは畳んであります。行の左の印を押すと済みになり、済みの印を押すと未着手に戻ります。画面で変えた内容は、次の信頼できる受付の入力に添えます。入力の送信に成功した分だけを伝達済みにし、送れなかった分と 1500 字の前置きに ID が入らなかった分は、後の入力にもう一度添えます。Claude の会話を再開する入力では、再開を確かめた返事が来るまで伝達済みにしません。

伝達前の変更がある項目には、受付の状態変更と削除を適用しません。`todo_update` はその項目の結果として、利用者の変更（`user_change`）と現在の内容を返します。受付は変更を伝えた入力のあとで、必要なら改めて変更します。本文と一言の修正は適用します。

## 受付への渡し方

信頼できる受付ターンの入力に、未完了の項目を前置きします。保存ファイルから毎回読むので、会話の要約、サーバーの再起動、受付の Claude と Codex の切り替えの後も届きます。作業役の報告を受け取るターンも同じです。

前置きは全体で 1500 字以内です。項目の行は 20 件まで、1 行 100 字までです。収まらない項目は件数と、入るだけの ID を示し、受付は `todo_list` で読みます。未完了がないときは一行になります。

## MCP

受付だけが使えます。対象のスレッドは接続で決まります。作業役、方針役、相談役、Issue の受け付け、GitHub の自動ターンには、道具も前置きも出ません。

`todo_list` と `todo_update` は、信頼できる受付ターンの実行中だけ呼べます。外部の入力を受けたターンでは呼び出しを断り、入力に前置きも添えません。ワークスペースからの依頼、Issue の作業開始、更新結果を受け取るターンがこれに当たります。メールを読むなどして途中から外部の入力を受けたターンも、その時点から同じ扱いです。そのターンへの追加の指示にも前置きを添えません。伝達前の画面の変更は、次の信頼できる入力まで残します。

- `todo_list`: 未完了の項目を返します。`include_done: true` で済みと削除済みも返します。
- `todo_update`: `changes` に `add`、`edit`、`set_state`、`remove` を並べます。順に適用して一件ずつ結果を返し、断った変更があっても残りは適用します。済みにするには `note` が必要です。同じ本文の未完了項目がある追加は、その ID を返します。

どちらも承認を求めません。

## 保存と上限

`threads/<id>/todo.json` に保存します。書くのはサーバーだけで、一時ファイル経由で置き換えます。シンボリックリンクは拒否します。読めないファイル（壊れた内容、未対応の版、2 MiB 超）は上書きせず、画面と受付に読めないことを知らせます。

| 対象 | 上限 |
| --- | --- |
| 本文 / 一言 | 200 字 / 160 字 |
| 未完了 | 100 件。超える追加は理由を返して断る |
| 済み / 削除済み | 新しい順に 200 件 / 100 件 |

ID は `T1` からのスレッド内の連番で、再利用しません。削除した項目には印を付けて残し、受付が足し直さないようにします。

## スレッドの操作との関係

| 操作 | TODO |
| --- | --- |
| アーカイブと復帰 | そのまま残る |
| ゴミ箱に移す | ファイルを残し、復元すると一覧も戻る |
| ゴミ箱から完全に削除、または期限切れ | `todo.json` を削除する |
| 引き継ぎなどで作る新しいスレッド | 空で始まる |

## 通信

プロトコル 76 以上の接続に、`TodoChanged { session, revision, items, unreadable }` を接続時と変更時に送ります。`items` は削除済みを除く全件です。`SetTodoState { session, item, done }` で一件を済みにするか未着手に戻します。75 以下の接続には送らず、その接続からの `SetTodoState` は無視します。古いサーバーは `todo.json` を読みません。
