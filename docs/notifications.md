# 作業の完了と応答待ちの通知

受付への送信から始まったターンの完了・失敗、承認・質問・目標の入力待ち、観測中のサーバー更新の結果を通知します。再接続で読み直した履歴、要約、途中経過、無言応答は通知対象外です。別のワークスペースのスレッドも通知対象です。バナーにはスレッドの題名と定型文が表示されます。

デスクトップの「設定 → 通知」で、通知の有効化、表示中の抑制、バナー、音を切り替えられます。スレッドを開いてから設定を表示すると、そのスレッドのミュートや作業役の終了通知を設定できます。既定ではウィンドウにフォーカスがあり、対象のスレッドを表示している間は通知を抑えます。同じスレッドでは 20 秒以内の通知をまとめ、完了の直後に入力が必要になった場合は追加で知らせます。試験通知には現在選んだバナーと音が使われます。

| 環境 | バナー・クリック・音 |
| --- | --- |
| Windows | パッケージ化していない exe でも通知領域のバルーンを試行します。表示中のバルーンからスレッドを開けます。Windows がバルーンを受け付けない場合は、タスクバーの点滅と、設定で有効にしたシステム音を使います。[通知領域の API](https://learn.microsoft.com/en-us/windows/win32/shell/notification-area) |
| macOS | 通知を許可したアプリバンドルは通知からスレッドを開けます。単体バイナリでは `osascript` の通知を試行し、音と Dock のバウンスでも知らせます。[NSApplication](https://developer.apple.com/documentation/appkit/nsapplication?language=objc) |
| Linux | セッション D-Bus の通知サービスを使います。`default` アクションに対応するデスクトップではバナーからスレッドを開けます。Wayland でウィンドウを前面に出せるかはコンポジターに依存します。音は `canberra-gtk-play` が利用可能ならサウンドテーマを、ほかの場合はデスクトップのベルを使います。WSLg では既定で通知がオフです。[Desktop Notifications Specification](https://specifications.freedesktop.org/notification/latest-single/) |
| Android | バックグラウンド接続と OS の通知許可を有効にすると、既存の「会話と作業」チャネルで知らせます。作業役の終了通知は接続設定で追加できます。タップすると対象スレッドを開きます。質問への回答はデスクトップで行います。旧サーバーではライブの承認通知を利用できます。 |

プロトコル 59 はライブ通知を追加します。デスクトップでは通知を出したクライアントが起動中に、バナーからスレッドへ移動できます。自己更新は実行中の状態を受信してから終了した場合に通知し、成功時には再接続後の状態も確認します。更新通知を押すとデスクトップではサーバー設定、Android ではアプリを開きます。Linux の `notify-rust` は MIT または Apache-2.0 で、既存の GPUI 依存と同じ版を使います。

## 実機確認

1. 設定の試験通知を押し、バナーと音を個別に切り替えます。再起動後に設定が残っていることを確認します。
2. 返信を待つ間に別のスレッドかワークスペースを開きます。返信通知を押して元のスレッドが開くことを確認します。同じスレッドを前面に置いた場合と、スレッドをミュートした場合は通知が抑えられます。
3. 承認または質問で止まる操作を試します。短い間に連続した通知、再接続時に再生される履歴、更新完了後の再接続も確認します。
4. Windows では配布先の exe で表示中のバルーンを押します。別ウィンドウが前面にあるときのタスクバー点滅と、通知が無効な OS 設定での表示を確認します。
5. macOS ではアプリバンドルと単体バイナリをそれぞれ起動します。通知を許可し、アプリバンドルではクリック、単体バイナリでは設定の案内と Dock のバウンスを確認します。
6. Linux では X11 または Wayland でバナーのクリックと承認・質問の優先度を確認します。WSLg と Windows を同時に起動し、既定では Windows 側だけが知らせることを確認します。
7. Android ではバックグラウンドに移り、通知をタップして別のワークスペースからでも対象の会話に移動することを確認します。
