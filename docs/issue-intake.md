# fuzukue への Issue の起票と受付

lab など別のワークスペースから利用者本人が起票するには、ブラウザーの「不具合報告」テンプレートか、次のコマンドを使う。再現手順、結果、期待した動作、バージョン、ワークスペースを書き、必要に応じて共有できるログや画像のパスを添える。

```sh
gh issue create -R example-owner/fuzukue
```

デスクトップの「不具合を報告」からも、宛先と編集済みの題名・本文を確認して起票できる。「送る」を押すと連携した本人の GitHub アカウントで送信し、`from-fuzukue` ラベルは付けない。未連携時はブラウザーの起票画面を開ける。lab からの報告先や非公開リポジトリ用の権限は [GitHub 連携の設定](github-auth.md) を参照。

受け付けてほしい Issue には `from-fuzukue` を付けない。受付から起票する場合は、起票元の `fuzukue.toml` で宛先を許可する。

```toml
[github]
issue_repos = ["example-owner/lab", "example-owner/fuzukue"]
```

`github_issue_create` の `repo` に `example-owner/fuzukue` を指定し、宛先・題名・本文に利用者が同意したら `confirm = true` で承認を求める。宛先の省略時はワークスペースのリポジトリを使う。許可一覧の省略時も同じリポジトリだけを許可する。明示した一覧には、使う宛先をすべて挙げる。別リポジトリへの起票結果は URL で返り、起票先のワークスペースが受け付ける。

## リポジトリごとの受付スレッド

1. スレッドのメニューで「このスレッドを Issue の受付にする」を選ぶ。メニューの先頭候補はワークスペース自身のリポジトリで、`[github].issue_repos` の許可先も選べる。受付はリポジトリごとに一つ。別のスレッドを選ぶと移動を確認し、「受付を外す」で解除する。一覧の「受付」バッジで指定先を見分けられる。
2. 新しい Issue や PR、追跡中のコメント、開閉、レビュー、CI などは、番号・リンク・投稿者と本文の短い引用を添えたシステムのカードで届く。既定で所有者の更新は受付が応対し、その他の投稿やエージェントの報告は通知する。GitHub の本文は外部資料として扱い、書き込みには既存の承認経路を使う。
3. 作業や議論を始めるときはカードの「この Issue のスレッドを開く」か、受付の `open_intake_issue_thread` を使う。作業スレッドから受付に戻れる。`list_intake_issues` で把握している未クローズの項目を読み、`mark_intake_issue` で対応済み・見送り・要確認を記録できる。
4. サーバーは項目の要約、状態、最終更新、作業スレッドと直近のジョブ ID をリポジトリごとに最大 128 件保持する。受付ターンには該当項目の要約と直近最大 3 件の更新を渡す。自動の受付ターンは同じリポジトリで 30 秒以上空け、見送り中の項目は通知だけを残す。

## 受付スレッドの指定がない場合

受付先の `fuzukue.toml` では、次のように設定できる。

```toml
[github]
intake = "all"
agent_markers = ["<!-- dot -->", "<!-- fuzukue -->", "<!-- lab -->"]
echo_window_secs = 600
```

- `all`（既定）では、監視開始以降に開かれ、取得時点で開いている Issue を受け付ける。紐づくスレッドがなければ「#番号 Issue の題名」で作業スレッドを立てる。GitHub で題名を編集するとスレッドにも反映する。利用者がスレッド名を変更した後は、その名前を維持する。開始前に開かれた `dot:*` の Issue も、新しい更新があれば従来どおりスレッドを立てる。
- `dot` は `dot:*` が付いた Issue を対象にする。`none` は自動作成を止める。紐づいている Issue や PR の監視は続ける。
- `from-fuzukue` は受付が自分のワークスペースのリポジトリへ内部の追跡用に起票するときのラベル。管理者は、そのリポジトリにこのラベルを用意しておく。受付は作成時にラベルと `<!-- fuzukue -->` を付けて、元のスレッドに紐づける。このラベルがある間は自動でスレッドを立てず、更新は通知にとどめる。

## 投稿者と応対

リポジトリの所有者または `gh` の認証アカウントからの投稿は、既定で「あなた」として受付が応対する。受付が返信・ラベル変更を行う場合は、スレッドの応対方針に従う。エージェントの報告とその他の投稿者からの更新は、既定で「知らせるだけ」。本文は外部の資料として扱い、作業の指示や書き込みの承認には使わない。

指定先の受付では `[github].intake` が新規 Issue の対象を決める。PR と追跡済み項目の更新は指定中に監視する。「あなた」の新規 Issue には、受付が空いたときに要約と次の操作案を示す。GitHub への返信には利用者の承認が必要。

利用者と同じ GitHub アカウントを使うエージェントは、`gh` で投稿するときも Issue とコメントに専用の隠し印を入れる。lab の受付が投稿する場合は `<!-- lab -->` を使い、受け付ける側の `[github].agent_markers` に登録する。判定はアカウント名より先に行う。手で起票する利用者本人の投稿には印を入れない。

サーバーは紐づいた項目に対するスレッドの GitHub ツール操作と、対象と操作を特定できる `gh` コマンドをメモリに記録する。利用者のアカウントから戻った更新が、記録した項目と操作に既定の 600 秒以内で一致すると、元のスレッドに短い通知を置く。コメント付きのクローズはコメントとクローズをそれぞれ照合する。一致した更新は未読や自動応対の上限に加算しない。期間は `[github].echo_window_secs` で変更でき、0 で照合を止める。コマンドは単独の `gh` 呼び出しで対象と更新内容を読み取れるものを扱う。

fuzukue 自身のコメントには `<!-- fuzukue -->` が付く。スレッドの操作に一致した場合は短い通知を置き、それ以外は従来どおり監視から除く。自動応対の上限は同じ Issue または PR に対して 1 時間に 3 ターン。 `[research].github_turns_per_hour` で変更でき、0 なら自動応対を止める。上限を超えた更新は通知として残る。
