# R-94 extraction preparation

The front desk can be a Claude Code session or a Codex app-server thread. In a blind request, that session authorizes the tool call and identifies its origin. The explicitly selected API backend and model determine the destination. [R-94 acceptance criteria](../roadmap/cards/R-94.md)

| Blind math section review | MCP `request_review` with `isolation` → `section::blind::request` → `prepare` → `sources::capture` → `section::blind::complete` → direct API. The section adapter owns permission checks, explicit selection, request-key deduplication, the allow list, scope and version checks, and the receipt. The single user message contains the response-format instructions, review criteria, scope header, and labeled excerpts in that order. ## Direct API behavior

Both blind entry points share `delegate::blind::Connection::complete`. The extraction boundary is the explicit input to this transport and the provider response it returns. The existing Claude Code and Codex app-server call sites do ordinary agent work and stay outside this boundary. [Direct transport](../crates/secretaire/src/delegate/blind.rs#L138)

| Provider | Request | Text and usage |
| --- | --- | --- |
| Anthropic Messages | POST `https://api.anthropic.com/v1/messages`. One user message, the explicit model, `tools: []` and `max_tokens: 4096`. Headers include the selected `ANTHROPIC_API_KEY` as `x-api-key` and `anthropic-version: 2023-06-01`. | Concatenates text blocks in order and skips thinking blocks. Delegation aggregates input and output token counts plus cache reads and creations when present. Missing input or output leaves the aggregate unknown. |
| OpenAI Responses | POST `https://api.openai.com/v1/responses`. One user input, the explicit model, `tools: []`, `store: false` and `max_output_tokens: 4096`. Uses bearer authentication from `OPENAI_API_KEY`. | Concatenates assistant output text in order and skips reasoning items and commentary messages. Delegation reads `usage.total_tokens` when available. |

Requests have no session history, filesystem access, or attachments beyond the inline text. Preserve the message bytes, including whitespace, UTF-8, and line endings. Credential lookup is provider-specific. Missing or blank credentials fail before sending. There is no fallback to the other provider or to a CLI. The HTTP client disables proxy discovery and redirects, uses a 90-second timeout and caps response bodies at 1 MiB. It surfaces HTTP status, timeout, transport and read errors. The decoder rejects malformed JSON, and the response parser rejects unexpected items such as tool calls and missing or empty text. Section review retains the raw response, including provider-native usage when returned. [Credentials and dispatch](../crates/secretaire/src/delegate/blind.rs#L91) · [Request and HTTP handling](../crates/secretaire/src/delegate/blind.rs#L216) · [Text and usage](../crates/secretaire/src/delegate/blind.rs#L299)

Cancellation is checked before scheduling the blocking HTTP work, again immediately before sending, and by both callers after completion. A request already in flight can still finish and incur usage. Section review saves a decoded response before its postflight cancellation check and reports interruption when that check fires. Generic delegation checks cancellation before decoding. [Transport cancellation](../crates/secretaire/src/delegate/blind.rs#L168) · [Section completion](../crates/secretaire/src/reviewers/section/blind.rs#L396) · [Generic completion](../crates/secretaire/src/delegate/blind.rs#L108)

## Contracts to carry into extraction

- Preserve section coverage independently of transport status. A completed response can legitimately omit some coverage. An output-limit response fails the review and can still leave a validated partial coverage record when the report parses. If the limit response contains invalid report JSON, the receipt records the response failure. Keep that diagnostic path when exposing truncation as an error from the shared function. [Coverage and failure handling](../crates/secretaire/src/reviewers/section/blind.rs#L449)
- R-94 requires both refusal and a differing returned model to fail through the new function. Today, section review rejects refusals while generic delegation can return refusal text. Both record the returned model without comparing it to the request. Preserve the requested route and any returned model in diagnostics so callers can explain these failures. [Section response parsing](../crates/secretaire/src/delegate/blind.rs#L185) · [Model recording](../crates/secretaire/src/reviewers/section/blind.rs#L440)
- The section receipt saves the criteria and excerpts separately and the response-format instructions in the assembled message. Its save-before-send behavior is the starting point for R-94's replayable snapshot. The extraction needs a pre-send snapshot of complete ordered instructions and materials, the assembled input, and the resolved route, version and settings. Add a replay fixture that mutates the original inputs and verifies exact route and body equality, and a save-failure fixture that observes zero provider calls. Record the direct API billing route and preserve unknown usage fields. Keep credentials in the transport only. [Packet fields and assembly](../crates/secretaire/src/reviewers/section/blind/sources.rs#L82) · [Pre-send persistence](../crates/secretaire/src/reviewers/section/blind.rs#L396)
- When implementing the strict contract, exercise both providers with missing credentials, refusal, tool calls, output limits, mismatched models, and absent usage. Assert that failures make zero ordinary-agent and alternate-provider calls. The current direct API mock captures the request immediately before HTTP I/O. [Mock transport boundary](../crates/secretaire/src/delegate/blind.rs#L229)

## Synthetic fixtures

The section workflow crosses each front-desk backend with each API provider. It seeds private `AGENTS.md` and `CLAUDE.md` instructions, card notes and attachments, a findings ledger, a prior-review memo, and excluded source lines. The provider fixture checks the endpoint, headers, and exact JSON bytes against an independently assembled message. It rejects private or out-of-range text. The workflow compares that message and each ordered excerpt with the receipt on disk and checks that the fixture credential is absent. The acquired-material workflow makes the same comparisons with an additional allow-listed CRLF excerpt and checks that the saved packet still describes the original material after its source changes. The generic delegation fixtures cover inline-only artifacts, whitespace-preserving text, rejected tool requests, and the absence of MCP tools, steering, and a worktree on blind jobs.
