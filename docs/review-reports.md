# 外部の査読報告

論文ビューの「査読」で投稿を追加する。投稿先、投稿したコミットまたはタグ、投稿日を入力し、判定と締め切りは分かっていれば記入する。日付は `YYYY-MM-DD` 形式。投稿 ID は投稿日と、小文字化して区切りをハイフンにそろえた投稿先から作る。たとえば 2026 年 11 月 20 日の JFA への投稿は `2026-11-20-jfa` になる。

## 報告を保存して指摘を確定する

投稿を開き、原文を貼り付けるかファイルを選ぶ。テキストファイルは UTF-8。PDF は参考資料と同じ `pdftotext` のレイアウト優先設定でテキスト化する。ファイルは 10 MiB、保存する原文は 256 KiB まで。保存した原文は Git で管理できる。

保存後、文体査読に設定したエージェントが読み取り専用のセッションで指摘の分割案を作る。原文は外部文書として渡し、文中の指示に従わないよう明記する。報告を開き、提案の行範囲、要約、関係するカード ID を編集する。項目を追加・削除できる。「指摘を確定」を押すと、サーバーが行範囲から引用を取り出し、報告番号ごとに `R1.1` から ID を振る。提案はサーバーのメモリにあり、再起動後は報告から再分割できる。

## 対応を記録する

指摘の一覧は状態で絞り込める。詳細では引用と関係するカードを並べて表示する。カード側の印からも該当の指摘を開ける。資料庫で報告や指摘を検索すると、確定済みの指摘があれば該当箇所に対応する指摘を開く。指摘のない報告では原文を開く。

「直す」を押すと、その論文に添付した別スレッドへ、確認済みの指摘の引用・要約と関係するカードを送る。開始時にスレッドと「対応中」を記録する。スレッドの処理が終わったら修正内容を確認して「直した」に変更し、編集欄で返答文と修正箇所を記入する。箇所は 1 行に 1 件で、たとえば `intro · cards/intro/statement.tex:12 · abc1234` のようにカード、行、コミットを記録する。「反論する」「対応しない」も選べる。

投稿内の「返答書の下書きを生成」は、確定済みの指摘を番号順に並べ、原文の引用、記録した返答文、修正箇所を Markdown に出力する。見出しの言語は `FUZUKUE_HARNESS_LANG` に従う。生成後は `response.md` を直接編集できる。再生成はファイルを置き換える。

## 保存先と道具

```
papers/<deck>/submissions/<id>/
  submission.toml
  reports/1.md
  points.toml
  response.md
```

`submission.toml` の項目は `venue`、`revision`、`submitted`、`decision`、`deadline`。`points.toml` は確定した報告番号の `split_reports` と `[[points]]` を持つ。行範囲は 1 始まりで両端を含む。`response.md` は生成時に作る。Workbench の査読欄と資料庫の `review_report` は WebSocket プロトコル 25 から使える。

- `list_review_submissions {deck}` で投稿、報告番号、確定した指摘 ID を一覧する。
- `read_review_point {deck, submission, point}` で原文の引用と対応を読む。
- `update_review_point {deck, submission, point, status?, cards?, fixed_locations?, response?}` で指定した項目を更新する。状態は `todo`、`in_progress`、`fixed`、`rebut`、`wont_fix`。
- `write_review_response {deck, submission}` で返答書の下書きを生成してパスを返す。既存の下書きがあれば置き換える。
