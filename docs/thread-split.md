# スレッドを分割する

分割の前に、直前のサーバービルドが `segmented-1` 形式を読めることが必要。サーバーの管理下にある直前のビルドを `/split check` が確認する。準備や切り戻しに、リリースインストーラー、サービスの再インストール、古いバイナリの直接起動は使わない。

1. 対象スレッドを開き、`/split check` を実行する。分割できるという通知を確認する。条件を満たさない場合は理由が表示される。この確認でスレッドやサーバーの状態ファイルは更新されない。
2. サーバーを停止する。隠しディレクトリを含めた `threads/` 全体と、サーバーの状態ディレクトリ全体を、属性を保ったまま別の場所にコピーする。元とコピー先のファイルのチェックサムを照合し、一致を確認する。
3. サーバーを起動する。対象スレッドでほかのコマンドやメッセージを送る前に `/split` を実行する。
4. 分割の完了通知を確認し、最新のスレッドファイルの先頭にあるメタデータに `format: segmented-1` があることを確かめる。

## 分割を戻す

対象スレッドで `/join` を実行し、結合の完了通知を確認する。最新ファイルと全セグメントの合計サイズの 2 倍に 16 MiB を足した空き容量が必要。サーバーを切り戻したり、スレッドをゴミ箱へ移したりする前に結合する。

バックアップから復元する場合は、サーバーを停止し、分割後の `threads/` とサーバーの状態ディレクトリを別に保管してから、バックアップした両方のディレクトリを復元する。バックアップより後の記録は復元先から失われる。GitHub のアクティビティなど Markdown にしか残っていない記録は、保管した分割後のファイルから確認できる。
