# 取得の台帳

資料庫の「台帳」で、必要な資料と取得状況を確認する。状態は「未着手」「取得済み」「利用者に頼む」「諦めた」の四つで、状態を選ぶと一覧を絞り込める。「取得記録」の件数を押すと、候補ごとの結果、取得済みファイルの保存先、SHA-256、取得日、出典、分かっているライセンスが開く。

## 候補を作る

「候補を提案」で、貼り付けたテキスト、ワークスペース相対のカードパス（例 `papers/example/cards/intro.md`）、既存の資料キーのいずれかを指定する。資料キーを指定すると、`ref.toml` の BibTeX、同じ資料フォルダにある `.bib` ファイル、PDF から抽出した参考文献節を調べる。PDF の抽出にはサーバー側の `pdftotext` が要る。

DOI、arXiv、PMC、GEO、Zenodo、GitHub、HTTP(S) URL を規則で拾う。BibTeX の同じ書誌項目にある識別子は一行の候補にまとめる。読み取り専用の Claude セッションには、抽出した行の題と種類だけを尋ねる。Claude を使えない場合は識別子と取得先の種類を表示する。識別子も URL もない引用は候補に入らない。

候補を確認したら「受け入れる」か「すべて受け入れる」で台帳に入れる。識別子に一致する実ファイルがすでに `references/` にある場合は取得済みとし、保存済みのパスとハッシュを登録する。確認待ちの提案は起動中のサーバーが保持する。

## 取得する

「取りに行く」は登録順に候補を試し、取得できたところで止まる。自動取得先は arXiv の PDF、PMC Cloud Service で OA と確認できた本文、Zenodo の公開ファイル、GitHub のコミット SHA で固定したアーカイブと raw ファイル、GEO の公開ファイルに限る。Zenodo のレコードに複数のファイルがある場合は、ファイルを指定した URL を使う。各リクエストは参考資料の HTTP クライアント、User-Agent、取得先別の間隔を共用する。同じ置き場所への自動取得は台帳の直近の試行から 15 分間休止する。

DOI の解決先や出版社のページは、台帳から自動リクエストを送らない。取得できなかった行は「利用者に頼む」に移る。「ブラウザーで開く」で候補を選ぶと、クライアント側の既定ブラウザーが開く。

- PMC は OA フラグとライセンスコードを Cloud Service のメタデータから読む。PDF が公開されていない場合は公開テキストを使う。 [PMC Cloud Service](https://pmc.ncbi.nlm.nih.gov/tools/pmcaws/) [NCBI のデータ形式](https://pmc-oa-opendata.s3.amazonaws.com/README.txt)
- GEO のアクセッション検索と SOFT の配置は NCBI の案内に従う。 [GEO のプログラムによるアクセス](https://www.ncbi.nlm.nih.gov/geo/info/geo_paccess.html)
- Zenodo は公開レコード API を参照する。GitHub のアーカイブは完全なコミット SHA を指定する。 [Zenodo API](https://developers.zenodo.org/) [GitHub のアーカイブ](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-source-code-archives)

## 利用者のダウンロードを結び付ける

サーバーは既定で、サーバーを実行しているユーザーの `~/Downloads` を監視する。変更するには、そのワークスペースのサーバー状態ディレクトリに `ledger-settings.toml` を置き、絶対パスで指定する。既定ワークスペースの場合、サーバー起動ログの `state:` が状態ディレクトリを示す。追加ワークスペースはその下の `workspaces/<id>/` に設定を置く。

```toml
downloads_dir = "/home/alice/Downloads"
```

サーバーとクライアントが別のマシンなら、ブラウザーで保存したファイルをサーバー側の監視先へコピーする。設定の切り替え時とサーバーの起動時に、監視先にあるファイルを起点とする。その後に現れ、サイズと更新時刻が連続した巡回で一致したファイルを対象にする。

ファイル名または PDF の先頭ページにある DOI・題を「利用者に頼む」の行と照合する。一意に一致すれば自動で結び付ける。複数の行に一致する場合や一致しない場合は、台帳のダウンロード候補から行を選ぶ。結び付けると `references/<key>/` にコピーし、ファイルの SHA-256 を記録する。元のファイルはダウンロード先に残る。確認待ちのダウンロード候補は起動中のサーバーが保持する。

## 保存と MCP

`references/ledger.toml` に確認済みの行をキー順で置く。候補は試す順に、取得記録は発生順に残る。新規取得では `references/<key>/ref.toml` を用意し、抽出可能な資料は既存のコーパス更新を経て資料庫の検索に出る。既存資料の照合では取得日にファイルの更新日を使う。

- `list_ledger {}` は確認済みの行を一覧する。
- `propose_ledger {input: {source: "text", text: "…"}}` は確認待ちの行を提案する。カードなら `{source: "card", path: "…"}`、資料なら `{source: "reference", key: "…"}` を渡す。
- `fetch_ledger {key}` は確認済みの一行について取得を試す。
- `read_ledger_attempts {key}` は一行の試行記録を返す。

作業役は未取得の資料を未取得と書き、その内容を推測で補わない。台帳の画面はクライアントとサーバーの双方がプロトコル 26 以上に対応すると開ける。
