# ワークスペース間の依頼

同じ secretaire サーバーに登録済みのワークスペース間で、題名と本文の依頼を送れます。利用者はデスクトップを端末トークンで接続します。サーバーと同じマシンで使う場合も、「設定 → サーバー → リモート」でループバック URL と端末トークンを設定します。端末トークンの発行方法は[リモート接続](remote.md#トークンで接続する)を参照してください。サーバーの管理権限と端末トークンは利用者が管理します。

1. 送り元のスレッドで「この不具合を fuzukue に送って。空の一覧を開くと選択が消える。現在の選択を保ってほしい」と頼みます。
2. 受付は宛先、題名、本文を下書きします。確認欄で宛先と本文・添付なしの表示を読み、「送る」か「やめる」を選びます。内容を変えるときは同じ会話で頼み直します。変更のたびに新しい版を確認します。完全承認モードでも、「送る」を押したときだけ配送されます。
3. 宛先のサイドバーから Inbox を開き、項目を選んで本文を読みます。既定では「着手する」を押すまで待機します。受信側の Inbox で「受付が着手する」に切り替えると、その後に届く依頼は受付が開始します。着手後は「作業スレッドを開く」で宛先側のスレッドに移動できます。
4. 受信側の受付に「依頼元に、再現する版を聞いて」や「完了と結果を返して」と頼みます。送り元は元のスレッドで質問を読み、同じ依頼への回答を頼めます。自由記述の返信にも同じ送信確認が出ます。

到着と受付の着手は、定型の更新として送り元のスレッドに表示されます。質問、回答、完了と結果も、対応するスレッドで確認できます。到着時に別のワークスペースを利用していても、送り元のスレッドを開けば更新が表示されます。

別のスレッドやワークスペースを開いている場合は、画面上部から Inbox を開きます。「確認待ちの下書き」から項目を選ぶと、送り元のワークスペースで宛先と文面を確認・送信できます。切断中に作られた下書きや、サーバー再起動前の下書きも、再接続後に元のスレッドと Inbox に表示されます。

依頼本文や返信は外部資料です。起動や着手は受信側の設定に従い、作業には受信側の規則と権限が適用されます。依頼の参照や返信にはそのスレッドでのみ使える ID が渡ります。送信元のスレッド・資料・ファイル・承認と、受信側の作業ログへのアクセス権は共有されません。

配送、下書き、履歴、返信経路、受信設定はサーバーの状態ディレクトリの `workspace-requests.json` に保存されます。同じ確認を再送しても依頼や返信は増えません。依頼を受けた作業スレッドは受信側の通常のスレッドです。着手を送る最中にサーバーが落ちた場合は、Inbox で着手が中断したことを表示します。同じ作業スレッドを確認してから着手を再試行できます。

デスクトップではプロトコル 69 以降で元のスレッドに送信確認が出ます。確認待ちの下書きを Inbox から開く操作と、受付への表示可否の通知には、サーバーとデスクトップの両方がプロトコル 72 以降に対応している必要があります。Android や旧版クライアントでも下書きは作れます。受付に確認画面を表示できない理由と、対応するデスクトップで下書きを開く手順を尋ねられます。添付付きの依頼と GitHub への配送は今後の項目です。
