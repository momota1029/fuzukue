# 完全承認モード

利用者が任せると決めた範囲で、手元でやり直せる作業を確認なしで進める設定。入り口は二つあり、どちらも既定は無効。

- スレッドのチャットで「すべて自動」を選ぶ。そのスレッドの受付と、そのスレッドから依頼した作業役に適用する。
- `/full-approval` を受付に送る。ワークスペース全体に期限つきで適用する。

どちらも作業役を隔離するセキュリティ境界ではない。個別確認を省いて監査を残す機能である。

コマンドの判定で防げるのは、うっかりした誤りだけである。作業は隔離されず、意図して回り込む操作は止められない。また、外部の入力を読んだターンから作業役へ指示が届くと以後の依頼は札を出すが、バックエンドが承認要求を送らないファイル編集は、その後も続くことがある。

## 確認なしで進むもの

- シェル、ファイル編集、手元で動く CLI の組み込みツール（作業場所の外の読み取りを含む）、サブエージェント。対象の組み込みツールは一覧で決めている（`Read`、`Grep`、`Glob`、`LS`、`LSP`、`Edit`、`MultiEdit`、`Write`、`NotebookRead`、`NotebookEdit`、`Bash` とその出力・停止、`Monitor`、`TodoWrite`、`Agent`・`Task` 系、`ToolSearch`、`Skill`）。`Monitor` のコマンドはシェルと同じく判定する。
- Fuzukue の対象 MCP ツール、作業の委譲、作業役の `run_tests` と範囲外のファイル書き込み、フォルダーの読み取り
- コミット、`git_integrate_patch`、確認済みブランチのマージ、`git pull`（早送りのみ）
- 個人情報の検査に指摘があるパッチの取り込み。指摘の場所はコミットの結果（`privacy_findings`）とスレッドの注記に残し、そのコミットがリモートに現れるまで、プッシュの確認に一覧で示す。指摘された文字列そのものは保存しない。記録は件数の上限で捨てない。指摘の場所を保存できない場合は、確認なしではコミットせず、札を出す。

## 利用者の判断を待つもの

次の操作は、下の例外を除き、どの承認モードでも札を出して待つ。後からモードを切り替えても、出ている札は承認されない。

例外は、作業役の起動設定で `approval` に `auto` か `never` を明示し、完全承認モードも「すべて自動」も効いていない状態で起動した作業役である。シェルやファイル変更などバックエンドの操作は従来どおりに扱う。`auto` は作業役の要求にサーバーが応答し、`never` はバックエンドが確認を省くため、次の操作も札を出さずに進むことがある。外部の入力で始まった作業は `ask` で起動する。

- プッシュ、公開、そのほかの外部への書き込み。`git_push`、GitHub の Issue の作成・コメント・ラベル・クローズ、研究 Issue の操作、GitHub 連携の切断、リリース。メールとワークスペース間の依頼は利用者が送信する。GitHub の自動応対に別途設定した応対方針は、この設定と関係なく適用する。
- 履歴や作業内容を失う Git 操作（`reset --hard`、`clean -f`、`restore`、`rebase`、`pull --rebase`、`commit --amend`、`checkout -B`、強制削除など）と、`.git` の削除・書き換え。`git checkout` は、名前がブランチかファイルかを文字列から区別できないため、新しいブランチの作成（`-b`、`--orphan`）、`--detach`、`checkout -` 以外は確認する。ブランチの切り替えには `git switch` を使う。
- 一覧にない組み込みツール。Web の取得と検索、メッセージの送信、予約実行などを含む。
- 内容を自動で判定できないコマンド（下記）
- Codex のファイル変更のうち、変更先がわからないもの、保護対象や認証情報の場所、`.git` の中を指すもの（リンクの先も調べる）
- CLI が `human_only` を付けた要求
- 管理者権限を使うコマンド（`sudo` など）とパッケージの導入
- サーバーの状態・設定ディレクトリ、SSH 鍵、保存されたログイン情報の読み書き
- Claude の受付と作業役が呼ぶ、Fuzukue 以外の MCP サーバーのツール（外部へ書き込むかを判別できないため）
- 自己更新、クライアント画面の共有、拡張の許可、取得台帳の行の確認
- 外部の入力で始まったターンと作業。メール本文などの差出人が書いた内容を読み取ったターン、GitHub の自動応対と Issue の取り込み、ワークスペース間の着信依頼と、そこから依頼した作業役には、どちらの入り口の自動承認も適用しない。

エージェントからの質問（`AskUserQuestion`、`request_user_input`）は承認ではないため、そのまま表示する。

### コマンドの判定と限界

シェルのコマンドは Bash の構文解析器（tree-sitter-bash）で読み、含まれるコマンドのプログラム名と引数を調べる。`env`、`timeout`、`flock`、`xargs`、`find -exec`、`bash -c`、ヒアストリングなどは、中で実行するコマンドまで調べる。次の場合は、安全と判定せず利用者に確認する。

- 構文解析に失敗した行、単語の途中の行継続
- 変数、コマンド置換、ワイルドカードで決まるプログラム名
- 操作の種類を左右する引数が実行時に決まる場合（`git $verb`、`git reset "$mode"` など）
- 理解していないラッパーやオプション（`watch`、`strace`、`env -S` など）、中身を読めない標準入力をシェルに渡す場合、未知の Git サブコマンド

この判定で防げるのは、うっかりした誤りだけである。隔離の仕組みではない。スクリプトのファイル、インタプリタの一行コード、ビルドやテストが実行するコード、一覧にないプログラムによる外部への書き込みは検出しない。

次の場合はコマンドがサーバーに届かないため、判定も確認もしない。

- Codex がサンドボックス内で承認要求なしに実行するコマンド。受付の `workspace-write` サンドボックスはネットワークと `.git` への書き込みを許さないが、サーバーの外の読み取りは妨げない。
- Codex の `untrusted` 方針が安全とみなす読み取りコマンド。認証情報のファイルを読むコマンドもここに含まれる場合がある。

## バックエンド側の確認

- Claude Code が `human_only` を付けた要求は、受付でも作業役でも札を出す。
- Codex が Fuzukue 以外の MCP サーバーのツールについて出す確認（elicitation）には Fuzukue が対応しておらず、呼び出しは失敗する。
- CLI 自身のログイン切れや利用上限の案内は Fuzukue では抑えられない。

## スレッドの承認モード

「毎回確認」と「計画」を指定したスレッドの受付は、`/full-approval` が有効でも確認する。そのスレッドから依頼した作業役には `/full-approval` を適用する。「編集は自動」は `/full-approval` が無効な間は従来の動作を続ける。「すべて自動」に切り替えると、そのスレッドの受付と作業役で待っている対象の依頼も承認する。

「すべて自動」でないスレッドでは、受付や Claude の作業役が読み取り・検索だけの Bash（`ls`、`rg`、`grep`、`find`、`cat`、`head`、`tail`、`sed -n`）を実行しようとして確認が必要になる場合、札を出さずに断り、ファイル用の道具の名前を返す。同じコマンドは 2 回まで、一回の実行で合計 12 回までで、それを超えると利用者に確認する。リダイレクト、置換、`-exec`、`-delete` などを含むもの、外部入力のターン、認証情報に触れるものは対象外。Codex の承認要求には理由を返せないため適用しない。

## 有効化・確認・停止

端末トークンまたはサーバー共有トークンで認証したクライアントで対象ワークスペースを選び、次のコマンドを受付に送る。サーバーが処理し、モデルには転送しない。

| コマンド | 動作 |
| --- | --- |
| `/full-approval` または `/full-approval 24h` | 24 時間有効にする |
| `/full-approval 1h`、`/full-approval 8h` | 指定した時間だけ有効にする |
| `/full-approval until-disabled` | 停止するまで有効にする |
| `/full-approval status` | 有効状態と期限を表示する |
| `/full-approval off` | 停止する |

同じ認証で `GET /settings/full-approval?workspace=<workspace-id>` を呼ぶと、現在の設定、監査、過去 24 時間のツール別の件数を取得できる。変更には同じパスへ JSON を POST する。

| JSON | 動作 |
| --- | --- |
| `{"mode":"full"}` | 既定の 24 時間で有効にする |
| `{"mode":"full","duration":"until_disabled"}` | 停止するまで有効にする |
| `{"mode":"off"}` | 停止する |

有効化すると、承認キューに残っている対象の依頼と、稼働中の受付や作業役が待っている対象の依頼も `full_mode` として承認する。待機中の処理には元の依頼への応答を一度だけ届ける。利用者の判断と競合した場合は、先に確定した判断が有効になる。サーバーが有効な設定を復元したときも、永続キューの対象を承認する。利用者に任せた依頼（時間制限のないパッチ取り込みの札を含む）は承認しない。フォルダーの読み取り依頼は 1 時間の許可に変わり、元の読み取りは再試行できる。

停止・期限切れで、新たな完全承認を止める。確定した許可はそれぞれの有効期限まで使える。その有効期間に起動した作業役へ停止を要求し、続ける場合は新しい作業役を起動する。既に発生した副作用や切り離されたプロセスは別途扱う。期限を設定し直す場合も、前の有効期間は終了する。ワークスペース画面での常設表示とワンタップ停止は R-73 で扱う。

## 作業役の実行範囲

どちらかの入り口が有効な間に起動する作業役は、既定で `full-access` になる。バックエンドはシェルの要求をサーバーへ送り、サーバーは利用者の判断が要るものを除いてすぐに応答する。「すべて自動」を途中でやめた場合や、外部の入力を読んだターンから指示が届いた場合は、以後の要求は札を出す。ファイル編集のようにバックエンドが要求を送らない操作は続く。

`fs_write`、`fs_edit`、`fs_apply_patch` による、ジョブの `touches` を超える対象の書き込みは、「すべて自動」または完全承認モードで自動承認する。ほかのモードでは承認を求める。ジョブの指示で指定された `target/` 配下の隔離チェックアウトと、そのジョブ専用の一時領域は、承認モードにかかわらずジョブの範囲に含まれる。保護対象のファイルとシンボリックリンクは引き続き書き込めない。

作業役は `run_tests` で自分のチェックアウトや隔離コピーのテストを実行できる。`dir`、専用のビルドディレクトリ `target_dir`、`tmp_dir` を指定できる。自動承認でないモードでは札を出し、実行するコマンドと設定された環境変数を示す。各スイートのコマンドはシェルと同じように判定し、利用者の判断が要るものは自動承認モードでも札を出す。受付の `run_tests` も、そのようなコマンドは確認する。作業役のテストはサーバーの環境変数を引き継がず、実行ファイルの検索パス、ホーム、ロケール、Rust と Lean のツールチェーンの場所と、スイートの設定、一時領域などの指定だけを渡す。ほかの変数が要る場合は、スイートの `env` に書く。`read-only` または `workspace-write` の実行設定を明示した作業役には提供しない。

Claude の作業役がチェックアウトかジョブ専用領域の中にディレクトリを作るだけの `mkdir` は、`read-only` を明示した場合を除き、どの承認方針でも確認しない。

`GET /settings/worker-execution?workspace=<workspace-id>` で保存値（`settings`）、次の起動に適用する値（`effective`）、bubblewrap の検査結果（`bubblewrap`）を取得する。同じパスに `{"sandbox":"workspace-write","approval":"ask"}` のような JSON を POST すると設定を置き換える。`{}` で既定の起動経路に戻る。

| `sandbox` | ファイルシステム |
| --- | --- |
| `read-only` | ホストを読み取り専用で見せ、ジョブ専用の一時領域だけに書き込める |
| `workspace-write` | 上記に加え、作業ディレクトリに書き込める。個別の MCP 操作は、引き続きツールの範囲や事前条件を検査する |
| `full-access` | ホストの OS ユーザーが持つ権限で実行する |

`approval` はネイティブの承認を `ask`（利用者に確認）、`auto`（作業役の要求へサーバーが応答）、`never`（バックエンドの確認を省略）から選ぶ。完全承認モード中と「すべて自動」のスレッドの作業役は、`effective` の値にかかわらず上記のとおりサーバーが応答し、明示された `sandbox` はそのまま使う。OS の書き込み制限は承認を省いても適用される。モードを停止すると保存された起動設定に戻り、保存値もない場合は従来の作業役設定を使う。

### bubblewrap の検査

サーバープロセスと同じアカウントで、実行ファイルの有無、非特権ユーザー名前空間、最小ルートでのコマンド起動、許可先への書き込み、範囲外の書き込み拒否、任意のネットワーク名前空間を検査する。サーバープロセスの存続中は最初の結果を時刻（`checked_at`、Unix ミリ秒）とともに保持する。失敗時には失敗した検査と stderr を返す。

WSL2 の試行では `unshare --user --map-root-user` は成功したが、bubblewrap のマウントが `bwrap: Failed to mount tmpfs: No such file or directory` で失敗した。検査に失敗した場合、明示的な `read-only` と `workspace-write` の起動はエラーになる。`full-access` は bubblewrap の検査結果にかかわらず利用できる。設定変更後にホストの状態を再検査するにはサーバーを再起動する。作業役の API とループバック MCP への接続に使うネットワークは、両サンドボックスでもホストと共有する。

## MCP の exec

完全承認または「すべて自動」が有効な間、利用者が開始した受付のターンでは、Claude と Codex のどちらからでも `exec` を呼び出せる。そこから依頼された作業役が `exec` を使うには、`full-access` として起動している必要がある。利用者の判断が要るコマンドは札を出してから実行する。Issue の取り込みや GitHub の自動応対など、外部入力で始まったターンでは実行できない。承認状態を実行直前にも検査し、監査に記録する。MCP クライアントがツール一覧を保持している場合は、モード切り替え後に一覧の再取得が必要になることがある。

`command` を指定すると、初期化ファイルを使わない非対話の Bash を標準入力を閉じて起動する。受付はワークスペースからの相対パスを `cwd` に指定する。作業役はチェックアウトからの相対パスを指定でき、省略するとチェックアウトのルートで実行する。`timeout_ms` の既定は 30 秒、上限は 120 秒。終了コード、シグナル、経過時間、標準出力と標準エラーを返す。期限切れ、停止、ターン・ジョブの取り消し、サーバーの停止・切り替えではプロセスグループを終了する。別のセッションへ自ら移ったプロセスはこのグループの外にある。サービスの環境変数は引き継がず、実行ファイルの検索パス、ロケールなどの少数の変数と一時領域を渡す。

長い出力はストリームごとに保存し、先頭・末尾、保存先、読み取ったバイト数を返す。どちらかが 4 MiB を超えると `output_limit` でプロセスグループを終了し、上限までの出力を保存する。バイナリ出力は Base64 で保存し、プレビューでは不正な UTF-8 を置換する。保存先のワークスペース相対パスを `fs_read`、`fs_search`、JSON・JSON Lines なら `jq` に渡して絞り込める。

長いテキスト系 MCP 結果もワークスペースの `.fuzukue/mcp-results`（既存の `.labo` を使う場合はその配下）に一時保存する。1 件 16 MiB、ワークスペース全体で 64 件・128 MiB が上限。24 時間で読み取り期限が切れ、次の保存時に古いファイルを削除する。スレッドに紐づく結果は、受付と同じスレッドの作業役がツールの応答にある正確なパスで読み取れる。

通常モードでの個別承認、OS 隔離、バックグラウンド実行は R-64・R-65 で扱う。

## 保存した結果の絞り込み

`jq` は通常モードでも使える読み取りツールで、端末の `jq` コマンドの代わりに組み込みの jaq を子プロセスで実行する。`path` と `filter` を指定する。JSON と JSON Lines の各入力値にフィルターを適用し、`raw: true` は文字列を引用符なしで返す。ストリームをまとめるには `[., inputs]` を使う。

入力は 16 MiB、出力は 64 KiB、実行は 5 秒、子プロセスのアドレス空間は 256 MiB が上限。CLI オプション、モジュールの読み込み、サーバーの環境変数は使えない。数値演算や正規表現の挙動は jq と異なる場合があり、jaq の `fromjson` は複数の値を読み込める。

## 設定と監査の境界

設定ルートは端末用資格情報を要求する。作業役の MCP キーは自身のジョブで許可されたツールに使え、サーバーの設定や受付専用ツールには使えない。自己更新やロールバックは受付の操作経路にある。設定ファイルはサーバーが権限 `0600` で原子的に置き換え、起動中はサーバーが保持する状態を使う。同じ OS アカウントで `full-access` を使うと、コマンドの判定をすり抜ける方法でこのアカウントの状態ファイルを書き換えられる。

サーバーが自動承認した依頼は、承認 ID、時刻、スレッド、ジョブ、ツール名、範囲、リスクを記録する。完全承認モードによる判断は `granted_by=full_mode`、スレッドの「すべて自動」による判断は `granted_by=thread_mode` になる。バックエンドが承認 RPC を送らず直接実行する場合は、通知された対象のネイティブ操作を記録する。返却する監査では引数をマスクする。稼働中の呼び出しに対する承認と一回限りの消費は一つの保存操作で行う。停止・再有効化やサーバーの再起動をまたいでも、依頼元と操作が同じ承認履歴を参照し、処理の再実行を防ぐ。実行結果が不明な場合は、その結果を照合してから再試行する。

フォルダーの読み取りに発行した 1 時間の許可には個別の有効期限と撤回がある。朝の報告での集計は R-63 を参照。
