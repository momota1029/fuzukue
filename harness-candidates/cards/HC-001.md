## 目的

    Run repeatable isolated acceptance for server self-update and rollback

## 使った手段

    Run a reviewed, fixed acceptance runner inside an isolated Linux PID and network namespace. Accept two validated full commit IDs and use only local Git objects and offline build dependencies. Start the older binary on loopback, connect a WebSocket client, feed a deterministic agent subprocess, and verify drain, progress extension, force, cancellation, durable queue replay and rollback. Save status, build IDs, process IDs and delivery counts to a recipe artifact.

## 既存ツールで足りなかった理由

    Worker commands cannot create loopback TCP sockets. Fixture tests can validate wait transitions and persistence but cannot verify a live WebSocket reconnect or queue delivery across a real executable swap. A fixed server-approved recipe can run the same checks with private loopback and a disposable state directory.
