> 現在のスレッドが上，下には他のワークスペースのタブが置いてあり，それぞれが開くようになっていると操作しやすい

> サーバはユーザフォルダに新しいワークスペースを立ち上げてソフトや論文の開発を始めてしまうくらい自由であるべき．そこはサーバ用のMCPがなんとかします

- コマンドラインで指定したプロジェクトが既定。既知のパス、タイトル、最終利用時刻は、既定プロジェクトのサーバー状態ディレクトリの `workspaces.toml` に記録する。
- 各ワークスペースは、最初に開くときにスレッド、デッキ、ビルド、ファイル監視、Claude/Codex の状態を用意する。待機が続いたエージェントのプロセスは終了し、次の会話でセッションを再開する。プロトコル v11 のイベントにワークスペース ID を添え、選択は接続ごとに管理する。
- サイドバーは上に選択中のスレッド、下に他のワークスペースを表示する。切り替えると、そのウィンドウで以前選択していたスレッドへ戻る。既存フォルダは「ワークスペースを開く」で指定する。
- サーバーは実体がホーム配下のディレクトリだけを受け入れる。`~/research` もふつうのワークスペースとして開ける（2026-11-21、利用者の判断。git と変更の履歴で守る）。リモート接続の認証と MCP のループバック制限は共通。
- 相手は `list_workspaces` で一覧し、利用者の依頼か明確な了承があるとき `create_workspace` で新規作成できる。作成後は場所を利用者に伝える。サイドバーに「新規」が付き、画面の切り替えは利用者が行う。

## 作業役のファイルアクセス

委譲された仕事はワークスペースのルートを使う。研究 Issue では、代わりに隣の `<project>-issue-<N>` を使う。選ばれたスキルの付属ファイルは、サーバー状態ディレクトリ内に作るジョブ専用の一時ディレクトリに置き、終了時に削除する。作業用の書き込み先はこのルートと一時ディレクトリ。システムの実行環境（`/usr`、`/etc`、`/bin`、`/sbin`、`/lib`、`/lib64`、`/opt`）とホームの `.cargo`、`.rustup`、`.elan`、`.cache`、`.codex/packages`、`.local/bin`、`.nvm`、PATH 上の `codex` の実体のディレクトリの既存パスを読取先に加える。Codex の砂箱はコマンドごとに Codex 自身を起動し直すので、その実体が読めないと全コマンドが失敗する（2026-11-21、Codex 0.169 で確認）。依存関係の取得やツールチェーン更新には、作業ルートの外への書き込みが必要なことがある。

利用者はワークスペースの `fuzukue.toml` で読取先を追加できる。絶対パス、`~/`、ワークスペースからの相対パスを受け付ける。Issue の場合も親ワークスペースの設定を読む。設定したパスは実在する必要がある。

```toml
[agents]
read_roots = ["~/research-references", "../shared-sources"]
```

ジョブ専用の一時ディレクトリは両方の作業役に `TMPDIR`、`TMP`、`TEMP` として渡す。共通の環境案内に続けて、ワークスペース直下の `.fuzukue/worker-notes.md` があれば作業役の指示に追加する。Issue の作業役にも親ワークスペースの案内を渡す。

- **Codex** は app-server の名前付き権限プロファイルを使う。ファイルシステムを読取先・書込先の一覧で指定し、ネットワークと権限の昇格を無効にする。既定の確認モードと計画モードでは作業ルートも読み取り専用にする。起動時にプロファイルの適用を確認できないバージョンでは、その仕事を開始しない。Issue の worktree が参照する親リポジトリの Git メタデータは自動で許可しないため、親側へのアクセスが必要な Git 操作は受付側で扱う。
- **Claude Code** は `PreToolUse` フックで `Read`、`Grep`、`Glob`、`Edit`、`MultiEdit`、`Write`、`NotebookEdit` のファイルパスや検索ルートを照合する。範囲外の操作は拒否し、既存のシンボリックリンクは実体で照合する。フックの実行形式と失敗時のブロックに対応した版が必要になる。Bash はコマンド中の明示パスを静的に確認し、範囲外のパスを検出したら stdio の許可要求を通して利用者に判断を求める。変数展開、スクリプト内のアクセス、コマンドが生成するパスはこの検査で判定できない。Bash の検査は OS のファイルシステム制限ではない。
- Codex の Linux プロファイルでネットワークを無効にすると、IPv4・IPv6 ソケットの作成と Unix ソケットの `bind` が拒否される。`allow_local_binding` はプロキシの設定で、制限中のシステムコールを許可する機能ではない。Claude Code のパス検査も外側のサンドボックスの制限を変更できない。ループバックだけを開く `[agents].worker_loopback` の設定は提供していない。ソケットを拒否されたときの撮影手順は [ヘッドレス撮影](../../docs/headless.md) を参照。
- 受付の権限は従来どおり。サーバー側の MCP は既存の作業役向けの道具に絞る。グラフなどの道具はワークスペースの設定に従って資料を返す。テストは作業役自身のシェルから実行する。
