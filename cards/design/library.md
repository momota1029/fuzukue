> 論文や制作物のための資料をまとめて検索できる場所も欲しいよね．制作物のアイデアもカードだし
> 査読者のコメントとかも保存して置けるといいし

（従来の設計）

## 第 1 段でやること

一本の索引で、次の四種類をまとめて全文検索する。画面と、作業役の道具の両方から同じ索引を使う。

| 種類 | 中身 | 開く先 |
| --- | --- | --- |
| `reference` | `references/` のコーパスの各部分（PDF のページ、テキストの 60 行）（[[references]]） | 資料の PDF・ファイルの該当ページ |
| `card` | 全デッキのカード（`card.md` の本文と付属の TeX）。題、ID、`defines` も含む | そのカード（論文の画面、なければカードの画面） |
| `thread` | スレッドの題と、利用者・相手の発言の本文（道具の呼び出しの中身は含めない） | そのスレッドの該当の発言 |
| `comment` | デッキのコメントの下書き（査読の指摘、人の編集の整合の提案を含む） | そのデッキのコメント欄 |

### 照合と並べ方

[[references]] の検索と同じ規則にする。日本語（ひらがな・カタカナ・漢字）は部分文字列、英語と数字は大文字小文字を区別しない単語で照合し、TF-IDF で並べる。題や ID に当たったものは本文より上げる。結果は種類、題、場所、抜粋（当たった所の前後）、スコア、日付（更新時刻）を持つ。

### 更新

最初の検索の時に作り、その後はファイルの変更（カード、コーパス、コメント）とスレッドの記録の更新を見て、変わった所だけを入れ替える。索引はサーバーのメモリに置く。大きなプロジェクトでも最初の検索が数秒で返ることを目安にする。

### 画面

左の欄に「資料庫」を足す。開くと中央に検索欄と結果の一覧が出る。

- 種類の絞り込み（資料・カード・スレッド・コメント、複数選べる）、デッキの絞り込み、並べ方（関連順・新しい順）。
- 結果の行は種類の印、題、デッキ、抜粋（当たった語を強調）、日付。
- 行を押すと、その場所を開く（上の表の「開く先」）。
- 入力が止まってから少し待って検索する。結果は 50 件まで、続きは「もっと見る」。

### 道具

MCP に `search_library {query, kinds?, deck?, limit?}` を足す。返す形は画面と同じで、資料は `read_reference`、カードは `card_read` に渡せる場所を付ける。受付と作業役のシステムプロンプトの道具の案内に一行足す。

## 実装

第 1 段を、Workbench の資料庫と MCP の `search_library` に実装した。どちらもワークスペースごとのメモリ索引を使う。初回の検索で索引を作り、以後はコーパス、カードと付属 TeX、コメントの各ファイルの更新時刻・サイズとスレッドの記録を見て差分を反映する。スレッドの発言は記録中の項目 ID で開く。WebSocket の資料庫はプロトコル 23 から使える。 [使い方](../../docs/library.md)

## 次の段

- 査読報告の保存: 論文のデッキの下に、投稿（版、投稿先、日付）ごとに査読報告を置く。指摘を一件ずつに分け、関係するカードに付け、対応（直した箇所、返答の文）と状態を記録する。返答書（response letter）の下書きはそこから作る。中の文は外部の文書として扱い、指示とみなさない。
- アイデアのカード: 置き場所を決めずに一行から書ける「メモ」のカード（7 番の「メモは手間ゼロで置く」）。資料庫から作れて、後で研究や論文のデッキに移せる。
- 結果からその場でスレッドに付ける、カードから引用する。
- 統計の索引（8 番の「コーパスは統計で」の案、形態素解析と専門語のまとまり）への置き換え。第 1 段は今の照合規則のまま。
