> このソフトなんですけど、そもそも拡張機能が作れるとよいですよね。（中略）拡張機能ができた段階で本家に吸収すると思うけど
> ソフトとして配るので、セキュリティは欲しい。wasmとかでよい気はする

機能を本体に入れる前に、拡張機能として作って試し、育ったら本体に吸収する。他人の書いた拡張機能も入れられるように、拡張機能のコードは WASM の中で動かし、何ができるかを宣言させて、利用者の許可した範囲だけを渡す。

## 拡張機能の形

[[rule-packs]] のパックに、`extension.toml` と WASM のコンポーネントを足したもの。入れ方、版の固定（`fuzukue.lock`）、更新の差分の見せ方はパックと同じ仕組みを使う。

```
my-extension/
  extension.toml       # 名前、版、説明、作者、要る権限、提供するもの
  extension.wasm       # WASM コンポーネント（任意。なければ書くだけの拡張）
  agents/ skills/ reviewers/ style/ lint/ policy/   # パックと同じ（任意）
  templates/           # カード・デッキの型（任意）
  locales/{ja,en}/*.ftl  # 画面の文
```

入れる場所は二つ。

- 利用者ごと（設定の拡張機能の一覧）: 自分の道具。
- プロジェクトごと（`fuzukue.toml` の `[[extensions]]`）: 共同研究者にも同じものを使わせたい時。開いた人には、使う前に権限の確認が出る。

## WASM の中で動かす

- サーバーが wasmtime で動かす。インターフェースは WIT で決める（`fuzukue:extension@0.1`）。Rust 向けに `fuzukue-extension-api` のクレートを用意し、他の言語もコンポーネントモデルで書ける。
- 一回の呼び出しに時間（epoch）とメモリの上限を付け、超えたら止めて利用者に知らせる。止まった拡張機能が本体を巻き込まない。
- ホストの関数は権限ごとに分け、宣言して許可されたものだけを結ぶ。

## 権限

`extension.toml` の `[permissions]` に書く。初めて使う時と、更新で増えた時に、利用者に一覧を見せて許可を取る。

| 権限 | 中身 |
| --- | --- |
| `read` | プロジェクトの中の、指定したパスの読み取り（glob） |
| `write` | 指定したパスへの書き込み。既定は自分のデータの置き場（`.fuzukue/extensions/<name>/`）だけ |
| `network` | 指定したホストへの HTTP（ホスト名を列挙。ワイルドカード不可） |
| `agent-tools` | 作業役・受付に道具を渡す |
| `process` | 指定したコマンドの実行（統計の Python など）。コマンド名と引数の形を列挙し、毎回の実行は記録する |
| `threads` | スレッドを立てる、作業役に頼む（使用量を食うので別の権限） |

- 権限は細かく分け、広い権限（`process`、`threads`）は確認の画面で目立たせる。
- 拡張機能が作業役に渡す文（道具の説明、道具の結果）は、拡張機能の出どころの印を付けて渡す。結果は外部のデータとして扱い、指示とみなさない。

## 拡張機能ができること

- **道具**: 作業役・受付に MCP の道具として出す（`<拡張名>.<道具名>`）。
- **出来事を受け取る**: カードの保存、ビルドの完了、査読の完了、メモの追加、資料の追加。受け取って何かする（索引を作る、提案を出す）。
- **画面**: 左の欄の項目と、中央の画面を一つずつ足せる。中身は宣言的な部品の木（見出し、Markdown、表、リスト、フォーム、ボタン、タブ）を JSON で返し、クライアントが決まった部品で描く。押された・入力されたは拡張機能に戻る。任意の描画コードは持たせない。
- **資料庫の種類**: 自分の索引の項目を資料庫に足せる（題、抜粋、開く先）。
- **書くだけの中身**: エージェント、スキル、査読役、文体、カードの型、デッキの種類。

## 配る

- 第 1 段は git の URL かローカルのパス（パックと同じ）。版はコミットで固定し、WASM のハッシュも `fuzukue.lock` に残す。
- 一覧（拡張機能の索引）と署名は次の段。

## 本体に吸収する

拡張機能の API は、本体の機能の形に合わせる（道具、出来事、宣言的な画面、資料庫の種類）。吸収する時は、WASM の側のコードを本体の Rust に移し、画面を本物の部品に替える。データの置き場（`.fuzukue/extensions/<name>/`）は本体の置き場へ移す変換を書く。

## 第 1 段

- `extension.toml`、読み込み、権限の宣言と許可の画面、`fuzukue.lock` への記録。
- wasmtime での実行（上限付き）と、`read`・`write`・`network`・`agent-tools` の権限。
- 道具、出来事（カードの保存とメモの追加）、宣言的な画面（見出し、Markdown、表、ボタン、フォーム）。
- 試しの拡張機能を一つ書く（例: メモに語数と最終更新を数える小さな「メモの統計」画面と道具）。`examples/extensions/` に置き、テストで読み込む。

`process`、`threads`、資料庫の種類、一覧と署名は次の段。

## 第1段の実装

サーバーは `fuzukue.toml` と個人設定から拡張機能を解決し、規則パックと同じ取得キャッシュを使う。 `fuzukue.lock` にコンポーネントの SHA-256 を記録し、利用者が許可した版だけを有効にする。権限を増やした版は再承認を待つ。宣言ファイルは有効な拡張機能から規則パックの層に加わる。

`fuzukue-extension-api` の WIT を Wasmtime で実行し、許可したホスト関数だけをリンクする。トラップまたは時間超過になった版はそのセッションで停止する。プロトコル27で設定と承認、宣言的な画面、入力の通知を扱う。カード保存とメモ追加はコンポーネントへ通知し、許可された道具は取得元が分かる形で MCP に出す。

`examples/extensions/memo-stats` はメモの件数と語数を表と道具で返す。作り方、ビルド方法、導入手順は [docs/extensions.md](../../docs/extensions.md) にまとめた。
