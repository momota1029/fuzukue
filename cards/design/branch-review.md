従来の設計と [[handoff]] にある、作業ブランチを監督役が確認して取り込む手順を画面に移した。プロトコル 34 のサーバーにつなぐと、サイドバーの「取り込み待ち」から開く。

- ローカルの `work/*` と、別の連結作業ツリーでチェックアウトしているブランチを並べる。先行・遅延コミット数、最終コミット、作業ツリーの場所、未コミットの変更、`work/issue-<N>` の Issue 番号を確認できる。基準は `main`、`origin/HEAD` があればその対象を使い、同名のローカルブランチを優先する。
- 選んだブランチについて、基準からのコミット、変更の集計、ファイル一覧、共通祖先からのファイルごとの差分を表示する。改名とバイナリを見分けられる。差分では追加を緑、削除を赤、ハンクの見出しを薄く表示する。変更履歴にも同じ表示を使う。
- 「テスト」は選んだブランチの作業ツリーで既存のプロジェクトテストを検出して実行する。件数、失敗箇所、出力を画面内に表示する。
- 「取り込む」は確認を経て実行する。ワークスペースで基準ブランチをチェックアウトし、基準側と作業側の未コミットの変更を片づけておく。確認したコミットを Git の試行マージにかけ、競合があれば作業ツリーを変更せず該当ファイルを表示する。成功時はローカルでマージし、変更履歴から取り込んだファイルの差分を戻せる。作業ツリーとブランチの削除は確認時に選べる（既定は削除）。Issue へのコメントや完了ラベルの付与、取り込み後の片づけに失敗した場合は画面内に表示する。
- 「捨てる」は確認を経て、未コミットの変更がない作業ツリーとブランチを削除する。履歴に残した先端の SHA から `git branch -- <名前> <SHA>` で復元できる。Git のガベージコレクションからコミットを保護するため、リポジトリに `refs/labo/discarded/<SHA>` を残す。
- 「差し戻す」は修正点を入力して紐づいた Issue にコメントする。
- 会話では `list_branches` と `branch_diff` で確認する。受付は対象と片づけの選択を利用者に確認し、承認後にだけ `merge_branch` に `confirm: true` を渡す。

撮影用のシナリオは [branch-review.json](../../tests/shots/branch-review.json)。フィクスチャに `main` と `work/issue-1` の作業ツリーを作り、差分と取り込みの確認画面を開く。
