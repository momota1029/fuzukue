外部のエージェントで進めていた仕事を、引き継ぎノートとともに fuzukue のスレッドに移す。残っている仕事は Issue として登録できる。

## 引き継ぎの中身

一つの Markdown（引き継ぎの書き付け）にまとめる。

- 目標と、今どこまで来たか（済んだこと、決めたこと、捨てた案とその理由）。
- 残っている仕事の一覧。それぞれ Issue にできる粒度で、受け入れ条件（Lean なら「この定理が `sorry` なしで通る、`#print axioms` が標準の公理だけ」）を付ける。
- 動いている作業者: Codex のスレッド ID、担当、worktree とブランチ、最後の状態。
- リポジトリの状態: ブランチ、worktree、コミットしていない変更、統合用のブランチ。
- 使っていた手順（スキル、スクリプト、監視の仕方）と、その置き場所。
- 元のセッションの記録の場所（`~/.claude/projects/…/<id>.jsonl` など）。

## 作り方（二通り）

1. **元のセッションが書く**（既定）: 元の Claude Code のセッションで「引き継ぎを書いて」と頼むと、上の型でリポジトリの `.fuzukue/handoff/<日付>-<題>.md` に書く。型はスキル（`fuzukue-handoff`、リポジトリの `skills/fuzukue-handoff/SKILL.md`）として配り、Claude Code にも Codex にも使える。2026-11-21 に書いた。この PC では `~/.claude/skills/` と `~/.codex/skills/` から同じものへリンクを張っている。元のセッションが一番よく知っているので、これが一番確か。
2. **fuzukue が読む**: 元のセッションがもう終わっている時は、fuzukue の「引き継ぐ」でセッションの記録（Claude Code の jsonl、Codex のスレッド）を選ぶ。読み取り専用の作業役が記録の後ろの方とリポジトリの状態から、同じ型の書き付けを作る。

## fuzukue での受け取り

- ワークスペース（例 `~/projects/compiler`）に新しいスレッドを立て、書き付けを最初の資料として付ける。受付は書き付けを読んでから話す。
- 残っている仕事は、利用者が確かめてから Issue にする（一括で作ってよい）。
- 動いている Codex の作業者は、スレッド ID で fuzukue の作業役として引き取れる（app-server の resume）。引き取った作業者は、fuzukue の作業役の一覧と会話に出る。引き取らずに、終わるのを待ってもよい。
- 使っていたスキルは、ワークスペースのスキル（ルールパック）として fuzukue の作業役にも渡す。

## 実装

- プロトコル 41。サイドバーの「その他」から「引き継ぎ」を開く。各ワークスペースの `.fuzukue/handoff/*.md` のうち `kind: handoff` のノートを見張り、題名、日付、移行元、残作業と作業者の件数を出す。
- 「引き継ぐ」でノートの題名を付けたスレッドを作り、ノートを最初の資料にする。受付はノートを読み、利用者の会話の口調で進捗と次の手を提案する。同じノートの受け取りを繰り返すと、開いている既存のスレッドに戻る。スレッドの「引き継ぎ」からチェックリストを開き直せる。
- 「残っている仕事」で選んだ項目をワークスペースの GitHub リポジトリに登録する。本文には項目の Markdown とノート・元記録の参照を入れる。手元のファイルにはサーバー上のパスを使う。「すぐ拾ってよい」を選んだ項目だけに `dot:ready` を付ける。作成した Issue 番号をスレッドに保存し、GitHub の紐づきを登録する。受付は `handoff_tasks` で候補を読み、利用者が選んだ項目を `create_handoff_issues` に `confirm: true` とともに渡し、表示された承認を待つ。
- 「引き取る」はノートのスレッド ID で `thread/resume` を呼び、同じ Git リポジトリに登録された worktree を指定する。再開後は同じ担当の続きから始め、作業役の一覧と会話に経過を出し、終了したら受付が伝える。元のプロセスが記録の書き込み権を保持している間は再開できない。失敗理由を表示したあと、「終わるのを待つ」で記録のターン終了を監視するか、「見るだけ」で記録の末尾に出た発言を読める。
- 「手順と道具」に挙がったローカルスキルは、有効化すると付属ファイルごと `.fuzukue/handoff-skills/skills/` に置き、ワークスペースのルール層から作業役に渡す。既存のルール層で利用できるスキルは有効と表示する。
- 「記録から引き継ぎを作る」には Claude Code の記録パスか Codex のスレッド ID を入れる。読み取り専用の作業役に会話の末尾と Git の状態、worktree、最近のコミットを渡し、サーバーが返された下書きを引き継ぎノートとして保存する。新しいノートは同じ一覧から引き継げる。

撮影シナリオは [handoff.json](../../tests/shots/handoff.json)。`scripts/shot.sh examples/lab tests/shots/handoff.json` で一覧とチェックリストを開く。

## 残っている課題

- 作業役ごとの作業場所: Issue ごとに git worktree を切り、終わったら差分を見て取り込む。今は作業役がワークスペースの作業ツリーを直接書き換える。
- 差分を見て取り込む画面（[[branch-review]]）。
- Lean の道具: ゴールと診断、`lake build` の対象を絞ったビルド、`#print axioms` の確認をテストとして。
