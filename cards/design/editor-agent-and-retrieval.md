1. **編集の入口（案）**　カードの編集状態と変更の確定はエディタ側が持つ。エージェントのカード編集はエディタ API に限り、直接書き込みを制限する。差分・取り消し・衝突検出を、個々の依頼で指示せずに働く仕組みにする。
2. **一か所置換と差分（実装済み）**　`card_edit` は指定部位で旧文が一度だけ完全一致するときに置換する。保存直前に元の内容を照合し、短い差分と周辺の検査結果を返す。
3. **書き込み範囲の衝突（一部実装）**　委譲の `touches` は変更予定パスの glob を表す。キューは通常の並行上限を超えて実行できるか判定するときに重複を調べる。範囲外の実変更は事後の警告で、書き込み時の制約は案の段階にある。
4. **開いているカードの同期（一部実装）**　ファイル監視で変更を拾い、保存時は基点のハッシュで競合を検出する。未保存の入力を保ちつつ、API 編集と開いている編集欄の版を揃える仕組みは案の段階にある。
5. **取り消し（一部実装）**　履歴画面から変更の取り消しやカードの復元ができる。`card_edit` の変更はファイル監視経由で履歴に入る。API 呼び出し単位で差分を記録し、その単位で戻す仕組みは案の段階にある。
6. **資料の種類ごとの検索（調査案）**
   - カード・定義は、既存の `graph_neighbors` と `card_context` で `requires` などの型付きの辺をたどる方法を優先する。
   - 文献・PDF は、既存のキーワード検索 `search_references` に埋め込み検索を加え、言い換えでも該当箇所を引けるか調べる。
   - スレッド・作業記録は全文検索と日付範囲で絞る。スレッドの本文検索は `search_library` にあり、日付範囲の指定は追加案とする。
7. **試行（方針決定）**　最初の埋め込み比較は、文献・PDF の用途を想定し、公開資料または合成データを使ってローカルモデルで行う。同じ問いに対してキーワード検索・埋め込み検索・両者の併用を比べ、上位の結果と取りこぼし、索引作成時間・検索遅延・メモリ・ディスク使用量を記録する。外部の埋め込み API は使わず、API 利用料を発生させず、原稿の内容を機外に送らない。改善が確認できた場合にカードへの適用も試し、その後、検索で得た起点からグラフをたどる。
8. **未決事項**　追加・更新・削除を索引に反映する時期、索引作成と検索のリソース負荷、ベクトルの保存先を決める。
