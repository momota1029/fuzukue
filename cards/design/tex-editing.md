2026-11-25 の要望の中心は、デッキ全体を一つの TeX 原稿として開き、直した内容をカードへ戻すこと。定理と証明を行き来しながら文章を直し、やがて原稿上で章をまたいで定理を並べ替えたり、新しい定理を足したりできるようにする。一枚の TeX 編集（[R-81](../../roadmap/cards/R-81.md)）は、部位の検証・版照合付き保存・組版を先に届ける段階。

## デッキ全体を TeX 文書として編集する

### 開く、編集する、反映する

1. カードを正本とするデッキの「論文編集」から「デッキを TeX で書き出す」を選ぶ。順に通読しながら編集できる `deck.tex` を作り、必要な組版素材があれば相対配置を保った編集用フォルダーを作る。
2. VS Code など任意のエディタで `deck.tex` を編集・保存する。素材を含むフォルダーは同じ配置で組版できる。エディタの保存やファイル監視でデッキを更新する処理は起動しない。
3. デッキで「編集した TeX を読み込む」を選び、編集したファイルと書き出し時の版を照合する。カードごとに変更を確認し、反映したいカードを選んで適用する。変更を構成や別カードと切り離せない場合は一組で選ぶ。適用結果から新しい編集用原稿を書き出せる。

この入口はカード正本のフォルダー型から始める。書き出しは編集用のスナップショットで、カード群・構成・プリアンブルを引き続き正本とする。

### 文書の組み立てと対応表

| 入力 | 書き出しと書き戻し |
| --- | --- |
| `structure.yaml` | デッキの組版設定を使い、部・章・節の見出しとカードの順序を再現する。独立して配置された証明はその位置に出す。見出し、証明の配置、文書冒頭など既存の構成要素にも区切りを付け、保存先を対応表に記録する。構成に載らないカードや組版対象外の項目があれば一覧に示す。 |
| `statement.tex` / `proof.tex` | 組版順に部位を展開する。ファイルに定理・証明環境が含まれる場合はそのまま使い、通常の組版が枠を補う場合は同じ枠を生成して本文と区別する。空白・コメント・改行コードを含む本文バイト列と、組み立て時に挿入した区切りや枠を対応表で分ける。 |
| `card.md` | `id` が対応のキー。`kind` と題名は既存の組版規則に従って必要なところに投影する。`requires`、リンク、ノート、出典、Lean などはカード側に保持し、通常の本文適用で更新しない。環境からカードを新設するときだけ、登録済みの環境と種類の対応を使う。 |
| ラベルと参照 | 著者が書いた `\label` / `\ref` などは保持する。生成ラベル、参照変換、節番号の生成は組版規則として扱い、書き戻す実テキストと区別する。カード ID と LaTeX ラベルは別々に照合する。 |
| プリアンブル | デッキ設定で選ばれたマクロ・パッケージ設定を、本文と別の範囲に置く。設定済みのエンジンとプロジェクト相対の素材参照を保つ。複数の設定・ファイルから生成した箇所には由来を記録し、元ファイルへ一意に戻せる範囲だけをプリアンブル編集の対象にする。 |

境界は通常の TeX コメントとして書く。PDF には現れず、外部エディタでカードのまとまりを切り貼りしても ID が付いていく。アプリ内では折りたためる。次は、同じカードの主張と証明が続く場合の概略。

~~~tex
% fuzukue:begin card=thm-example part=statement
\begin{theorem}\label{thm:example}
  $a^2 \ge 0$.
\end{theorem}
% fuzukue:end card=thm-example part=statement
% fuzukue:begin card=thm-example part=proof
\begin{proof}
  It is a square.
\end{proof}
% fuzukue:end card=thm-example part=proof
~~~

文書ヘッダーに形式版・デッキ識別子・書き出し ID を入れ、その ID でワークスペース側の対応表と基点を引く。対応表はカード ID、部位、必要なら掲載箇所ごとのキー、元のファイル、部位と生成部分のバイト範囲、行対応を持つ。コメントからファイルパスや適用先を受け取らず、書き出し時の対応表と現行デッキで解決する。文中の行番号や `\label` が変わっても、正しい区切りを保ったブロックは同じカードとして扱える。

組版に効く改行やコメントを勝手に足さない。区切りを置ける箇所を検査し、元の `\input` 境界に相当する改行・`%` の扱いは生成側で持つ。安全にインライン化できない `\input` や素材を含むデッキには理由を表示する。後に同じ対応表で、主ファイルから部位別の編集用コピーを `\input` する複数ファイル構成も提供できる。各パスは書き出し時に割り当て、読み込み先は同じカード ID と部位で管理する。再掲された部位は一つの候補にまとめ、掲載箇所ごとの編集が食い違う場合は衝突を表示する。

### 文書の差分をカード操作に戻す

読み込みでは、登録したコメントの位置と LaTeX の静的な字句構造を照合する。コメント・逐語環境内に例として書かれた区切りや、数式の中に現れた環境名をカード境界として解釈しない。読み込んだ内容を正本に対する操作に変換し、一時領域で再構成して、適用対象にした TeX と構成の差分が再現することを確かめる。

| 原稿の変更 | 差分に出す操作 |
| --- | --- |
| 既存部位の本文を直す | 同じ ID の `statement.tex` / `proof.tex` を更新する。生成した枠や変換後の参照に変更があれば、保存先を確定できる操作として別に扱う。 |
| 移動・並べ替え | 区切り付きのブロックの順序と所属する節から `structure.yaml` の変更を作る。章・節の識別は書き出し時の対応を使い、同名見出しも区別する。後置きの証明は独立した配置項目として動かせる。移動元・先と組版番号や参照への影響を示す。 |
| 定理などを足す | ブロック外のトップレベルにある登録済みの定理系環境から新規カード候補を作る。環境から種類と題名を取り、隣接する証明は対応が一意な場合に候補に含める。採用する ID、配置、種類、依存候補をプレビューで確認する。ID はデッキ内で一意に割り当て、ラベルによる既存カードとの上書きはしない。依存候補は既知の参照から提示し、利用者の確認後に `requires` へ入れる。 |
| 削除する | 元の区切り一組が消えた場合は、削除と区切りの消失を区別できるまで保留する。明示的に削除を選んだ場合に、構成から外すだけか、カード自体を削除するかを選ぶ。カード自体の削除ではノート・Lean・出典と確認できた参照元を示し、残るリンクや依存の処理も承認する。 |
| 分割・結合する | 元の部位にまたがる変更を検出したら、利用者が分割・結合を選び、残す ID、新しい ID、証明とノートの帰属、移す依存・参照を指定する。関係する旧カード・新カード・配置とメタデータは一つの変更として扱う。 |
| `\label` を改名する | 同じカード・部位の変更として旧名と新名を示す。デッキで解決できる一意なラベルと対応形式の `\ref` / `\eqref` などを一緒に確認・更新する。重複、動的な参照、別文書からの参照などを確認できる範囲で示す。カード ID と ID ベースの `requires` はそのまま使う。生成ラベルは生成元の設定を変更する経路に案内する。 |
| プリアンブルを直す | 印を付けた範囲から元のプリアンブルへの差分を作る。影響する組版ルートを示し、プリアンブルの変更が必要な本文差分は一緒に確認する。生成設定や外部パッケージのファイルを編集先として推定しない。 |
| カード間に地の文を書く | 空行とユーザーのコメントも含めて差分に出す。既存の文書冒頭など保存先が明確な範囲はその元へ戻し、本文中の新しい段落やコメントは配置を確認して解説カードにするか、利用者が指定した既存の解説カードに入れる。未分類の文章があれば、行と編集中の原稿を保持して適用を保留する。 |

片側だけの区切り、重複した ID・掲載キー、未知の ID、交差した区切り、基点にある部位が消えた場合は行と該当カードを示す。基点から区切りの復元候補を提示できるが、本文やラベルの類似だけで適用先を確定しない。利用者が区切りを復元するか、構成編集を使える段階では削除・分割などの意図を明示してから、再読み込みする。初期版では境界の破損がある文書からの適用を止める。

### プレビュー、競合、確定

- 書き出し時に、カード単位で存在・ID・ファイル対応と、`statement.tex` / `proof.tex` / `card.md` の生バイトの指紋と復元できる版を記録する。`structure.yaml`、プリアンブル、解釈に使ったデッキ設定も別々に記録する。ハッシュは同一性の検査に使い、差分と三者比較には基点の本文を使う。
- 読み込み時のカードと書き出し時の基点、編集した原稿を部位ごとに比べる。片側だけの変更、両側で同じ結果になった変更、異なる部位や重ならない箇所への変更を区別し、合わせられる場合はマージ候補を出す。同じ箇所、削除と編集、別々に動かした同一カード、ラベルや種類の食い違いは競合として三者を表示する。編集対象外のノートだけが並行して変わった場合は現行ノートを保持する。順序が両側で変わった場合は、意味の異なる移動を勝手に一列に直さず、人が配置を確定する。
- カード ID・題名、主張／証明の差分、書き込むファイル、追加・移動・削除、参照への波及、構成とプリアンブルをプレビューに載せる。競合は採用する側または手動修正を選んで解消する。選択したカードと付随する変更で差分を作り直し、依存のある変更は一緒に選ぶ。選択分に未解決の競合、再構成の不一致、書き込み不可があれば確定を止める。
- 選択分を一つのトランザクションにする。R-81 と部位の検証・版照合処理を共用し、選んだカードの変更をまとめて準備する。同じデッキへの書き込みを直列化し、プレビュー後に正本・編集用ファイル・設定の版と権限を照合する。更新ファイル・以前の内容・処理の進捗を一時領域と復旧用の記録に準備し、全体を確定してから新しい表示、組版入力、履歴に公開する。失敗・中断時は復元してから通常の読み書きを再開する。外部のファイルエディタなどとの競合で安全に復元できない場合はその版を保全し、復旧が済むまで読み書きと組版を止める。書き込みを直列化できず安全な確定・復旧を提供できない場所では、差分の確認までにとどめる。原子的な確定の範囲は fuzukue のデッキ操作と組版で、書き込み中にファイルを直接読む外部ツールの観測までは含まない。
- 履歴には一回の適用と逆差分を残す。取り消しも一組として現行版を照合し、後から入った編集を巻き戻す可能性がある場合は逆差分をプレビューして解消する。部分適用や並行マージの後も編集用ファイルを無断で置き換えない。未採用の下書きを保持し、残りを再プレビューするか、確定したデッキから新しく書き出せる。

### 組版、SyncTeX、アプリ内エディタ

書き出しには通常の組版と同じルート設定、エンジン、素材を使う。ローカルで組版する場合は書き出した編集用フォルダーで実行する。取り込んだ原稿はプレビューだけでは自動実行しない。アプリから確認する場合は明示的に組版を選び、承認候補の組み立て文書を隔離した作業領域で、通常の組版の実行権限に従ってビルドする。組版結果は TeX の適用結果と別に示す。候補が失敗した場合は診断を開けるようにし、成功した本番 PDF は保持する。

組み立て文書に対するビルドごとに PDF、SyncTeX、入力の指紋、書き出し ID、行対応をそろえる。PDF↔`deck.tex` の順引き・逆引きと、編集行↔カード ID・部位の移動に使う。生成枠を指す位置なら構成やプリアンブルの該当箇所を開き、部位までしか分からなければその粒度を示す。編集中の版と異なる場合は対応するスナップショットを開くか再ビルドできるようにする。古い SyncTeX を現在の行番号へ当てない。

アプリ内エディタも外部エディタと同じ書き出し・読み込み・承認を使う。文書全体を一つの下書きとして持ち、カードの境界を折りたたみ、カードから該当行へ移動できる。外部ファイルを開く場合は保存済みの版を読み、アプリ内に未保存の変更があれば切り替え時に差分を確認する。実ファイルを持つ編集用フォルダーでは既存の TeX 補助を利用できる。仮想ビューでも差分確認と反映は同じ経路を通す。

### LaTeX の本を取り込んだデッキとの関係

`import-latex` は任意の既存 LaTeX から新しいデッキを作る入口。デッキ文書の読み込みは既知のデッキの ID と書き出し基点を使う更新操作。定理系環境の静的な検出や組版の比較は共用できる。原本同期型では `manuscript_main` と配下の元原稿を編集して、ラベルと部位対応から同期する（[R-83](../../roadmap/cards/R-83.md)）。カード正本に移行したデッキでは、由来のリンクを保ったままデッキ文書の編集を使える。原本同期型でカードを正本とする適用は、原本との照合と書き戻し経路が確定するまで止める。既存原稿の選択や正本の切り替えは、デッキ文書の読み込みでは行わない。[取り込み後の移行](../../docs/book-harness.md#移行の段階)

### 適用を止める条件

- デッキ・形式版の不一致、基点や対応表の欠落、UTF-8 で読めないファイル、壊れた区切り、ワークスペース外を指す書き込み先、版切れ、権限不足では書き込まない。対象の行・ファイルと、書き出し直すか対応を修復するかを示す。
- 動的な `\input`、境界に効く条件分岐やカテゴリコード変更、マクロが生成する環境・ラベル、対応不明な独自環境、重複ラベル、元へ戻せない枠や参照変換では、静的に対応を確定できるまで適用を止める。本文にある既存マクロの呼び出しはそのまま保存できる。生成物、外部素材、独自ビルド設定はそれぞれ元の編集先を示す。
- 初期版は既存の本文ブロックの編集を受け付ける。並べ替え、削除、追加、ラベル改名、プリアンブルやカード間の文章を含む差分は、該当範囲と理由を示して止める。前段階で作った編集用ファイルも、対応する基点が残っている間は前段階の規則で読み込む。

## カード・元原稿・組版結果から編集する

R-87 を一枚の TeX 編集に続く優先機能とする。以下の入口では、選んだカードや元原稿、組版結果を起点にする。

| やりたいこと | 操作と結果 |
| --- | --- |
| 一枚のカードの数式を直す | カードの主張または証明で「TeX で編集」を開き、数式環境や改行を直す。差分を確認して保存すると、同じカードの表示が更新され、組版の結果を確認できる。 |
| 本の原稿を直接直す | 対応する元の `.tex` を開くか、外部エディタで編集する。デッキの「原稿から同期」で影響するカードと部位の差分を確認して適用する。カード側にも修正があれば、両方の変更を比べて解消する。 |
| 組版されたものを起点に直す | PDF の位置から生成 TeX の該当箇所を開き、編集用のコピーで修正する。「カードに反映」で書き戻せる差分と対象部位を確認して適用する。次のビルドで変更が再現される。 |

## 正本と書き込み先

| デッキ・編集対象 | 正本 | 保存・反映の扱い |
| --- | --- | --- |
| カード正本のフォルダー型 | カードの `statement.tex` と `proof.tex` が組版本文。`card.md` が ID・種類・依存・ノート、`structure.yaml` が順序を持つ。 | TeX モードと通常のカード編集は同じ部位を更新する。両方で開いた下書きの競合は同じ保存経路で検出する。 |
| カード正本の writing harness | Markdown の `Statement`・`Proof` または組版対象の解説本文。frontmatter がメタデータ、`structure.yaml` が順序を持つ。 | TeX を含む元の部位を直接開くか、生成ビューから逆変換できた本文だけを元の範囲へ戻す。frontmatter、節見出し、`Notes`、`Shortcuts` は保持する。 |
| 原本と同期する取り込み本 | `manuscript_main` 以下の原稿が組版本文・構成・プリアンブルの正本。カードの TeX とデッキの構成・プリアンブルは取り込んだ写し。ノート・タグ・依存・Lean などカード固有の情報はカード側が持つ。 | 外部で保存された原稿は明示操作でカードに同期する。カードで行った本文修正は原稿への適用候補として保持し、承認した場合に限って原稿へ書き戻す。適用時にカードの写しと照合情報もそろえる。 |
| 取り込み後にカードへ移行した本 | 明示的な切り替え以降は、カード・デッキのプリアンブル・`structure.yaml` が正本。 | 取り込み元への参照は由来として残せる。移行前に保留中の変更を解消し、権限と同期状態を確認する。 |
| `build/` の組版結果 | 選択した成果物に対応するカードまたは原稿。 | 生成 TeX はビルドごとの成果物。編集用コピーの差分を正本に適用し、ビルドで生成し直す。 |

モードはデッキ単位で明示する。既存の取り込み本には、原稿の場所を示す `manuscript_main` や取り込み時のハッシュが残っている場合がある。これらの有無や原本の消失でモードを推定・切替せず、同期を有効にする際に利用者が選ぶ。従来の保存はデッキが同期に参加するまで従来どおり扱う。参照用・読み取り専用の原本は、原本→カードの更新だけを提案できる。原稿とカードの両方への書き込みが必要な操作は双方の権限を確認する。[現行の取り込みと移行手順](../../docs/book-harness.md#移行の段階)

## 対応付けとマクロ

- フォルダー型のキーはデッキ・カード ID・部位。`statement.tex` / `proof.tex` と `card.md` の対応を使う。Markdown 型は同じキーに、元ファイルと部位の範囲を添える。バイト範囲は特定の入力版に属し、行番号は表示や移動に使う。
- 取り込み本では、原稿のルート、入力ファイル、部位、固有のアンカーをカード ID と結ぶ。定理の生の `\label` を優先し、証明は対応する定理のアンカーと証明部位を一緒に使う。ラベルがない場合は、静的に識別できる節・環境と前後の文脈で候補を探し、人が一意の対応を確認してから登録する。必要なら原稿に安定したラベルを付ける。行の挿入で位置が動いてもカード ID は保つ。重複やラベル変更、複数箇所への展開は、範囲や旧ハッシュだけで推測せず、対応を確認し直す。
- 現行の取り込みはラベル、または章・節・種類・題名から ID を作る。`source`・`additional_sources`・`proof_sources` は元の行範囲、`source_sha256` はその行末込みのバイト列の SHA-256。範囲は主ファイルの親を基点にする。同じ行に別の断片がある場合や、入力ファイルをまたぐ場合は行範囲だけでは書き戻せない。同期用の対応表に、確定したアンカー・部位ごとの正確な範囲・同期基点を持たせる。`reading_sync_check` はずれと未対応定理を調べる読み取り専用の入口として使う。[インポーター](../../crates/fuzukue-cards/src/latex_book.rs) · [原稿の照合](../../crates/fuzukue-cards/src/reading_sync.rs)
- 既存の `source_id` は翻訳元の「デッキ#カード ID」を参照する。`source_fingerprint` は改行と空白を正規化し、Notes を除いた本文と一部のメタデータから計算する翻訳用の指紋。これらは翻訳の追跡に残す。TeX 用の対応表では原稿アンカーを識別子に使い、部位・ファイルと同期基点の照合には改行や空白を含む別の完全なハッシュを使う。[翻訳元の解決](../../crates/secretaire/src/cards/translation.rs) · [翻訳用の指紋](../../crates/fuzukue-cards/src/translation.rs)
- カード内のマクロ呼び出しは展開せず保持する。補完やビルドには対象ルートと実際のプリアンブルを使う。カード正本の共有マクロはデッキ側のプリアンブル（またはデッキ設定）で、原本同期型の共有マクロは原稿側の定義箇所で編集する。コピーされたプリアンブルを同期する場合は影響するビルドを差分に添える。プリアンブルや章構成の更新を安全に対応付けられない段階では、該当ファイルを開く導線と差分の報告を用意し、本文の同期は適用前に止める。

## 往復できる範囲

ここでの「可逆」は、未編集の範囲のバイト列を保持し、受け付けた変更が正本からの再抽出・再生成で再現されることを指す。空白、コメント、改行コード、マクロ呼び出しも保存対象。表示用に整えた文字列や整形コマンドの出力を暗黙に保存しない。

| 経路 | 適用できる変更 | 適用を止める変更 |
| --- | --- | --- |
| カードの TeX → 同じカード | 既存の `statement.tex` / `proof.tex` を直接編集する。Markdown に埋め込まれた生の TeX は、部位を取り直して対象バイトだけを差し替えられる場合に扱う。 | 部位をまたぐ編集、挿入後に Markdown の節境界が変わる編集。別のカードや構成も変わる変更はその操作を案内する。 |
| 原稿 ↔ カード | まず一意に対応する既存の定理または証明の、単一ファイル内の連続した本文を扱う。原稿は対象範囲だけ差し替え、カード化するときに足した末尾の `%` と改行などは、記録された境界として扱う。原稿への書き戻し後に再抽出して一致を確かめる。 | アンカー・環境境界・入出力の分割を変える編集、動的な `\input`・条件分岐・マクロ展開に依存する範囲。定理の追加・削除・移動や章見出しの変更は影響を示し、構成更新を伴う同期に回す。 |
| 生成 TeX → カード | 対応表が元の編集可能な連続範囲に一意に結ぶ変更。元の範囲に差分を適用して再生成し、承認する生成差分を再現できた場合に反映する。再掲があれば、同じ変更が出る箇所も表示する。 | 生成した環境枠、節見出し、ラベル・参照変換、整形された証明ステップなどへの変更。生成コマンドや `\input` 先の変更、複数カードや対応しない範囲をまたぐ編集。元ファイル・設定へ誘導し、曖昧な箇所は適用しない。 |

現行の writing harness の `<成果物名>.sources.json` は生成ファイル・行からカード ID・Markdown パス・行を引くためのもの。環境枠に本文と同じ行が割り当てられる場合もあり、書き戻しの範囲は決められない。書き戻しには別途、成果物の版、生成時の本文バイト範囲、部位、元範囲と版、および生成専用部分の印を記録する。編集用コピーを同じ版の生成物と比較し、境界への挿入を含めて対応が一意か確認する。フォルダー型で組版ルートが `\input` する実体は、その部位の「TeX で編集」を直接開ける。[生成処理](../../crates/secretaire/src/harness_build.rs) · [Markdown の部位選択と保存](../../crates/fuzukue-cards/src/markdown.rs)

## 同期、差分、競合

同期に成功したときの原稿断片とカード断片を、部位ごとの共通基点として保持する。それぞれの生バイトの SHA-256 と、三者比較に使える本文または復元可能な版を記録する。`source_sha256` は従来どおり原稿の行範囲の検査に使う。旧デッキでは、記録済みの原稿ハッシュと再抽出した本文が現行カードに対応すると確認できた時点で基点を作る。旧版を復元できない、またはすでにずれている場合は、原稿とカードを並べて差分を手動で解消する。再抽出で一致を確かめてから基点を作る。ハッシュだけで本文の一致やマージを推測しない。

| 基点と比べた変化 | 提案 |
| --- | --- |
| 原稿だけが変わった | 再抽出した差分をカードに反映する。本文が同じで位置だけ変わったカードは、その位置と行範囲ハッシュの更新も表示する。 |
| カードだけが変わった | 正本への反映を指示された場合に、原稿への差分を作る。「原稿から同期」では変更を保留として表示する。 |
| 両方が同じ内容に変わった | 一致の根拠を示し、同期の記録のみ更新できるようにする。 |
| 両方が別の内容に変わった | 対応する生 TeX の基点から三者比較する。重ならない変更は候補にまとめる。重なる変更や変換後の対応が曖昧な箇所は原稿・カード・基点を並べ、片方の採用か手動編集で解消する。原稿も変更する候補には、その書き込み先を明示する。 |

適用前に、対象デッキ・成果物、書き込むファイルとカード部位、TeX の差分、カード表示の変化、更新する対応・構成、適用できない箇所と理由を確認できるようにする。必要な変更が一つでも未解決なら、その提案全体を保留する。範囲を絞り直す場合は別の差分として作り直す。原稿とカードの一致は再抽出で、生成 TeX の反映は再生成で、適用前の一時領域で確認する。原稿や生成コピーからの反映では、組版できる場合は適用前の候補もビルドし、差分と一緒に結果を表示する。途中の成果物は本番の PDF・SyncTeX と入れ替えない。

確認後に入力ファイルの版、アンカー、対応表、対象の権限を再照合する。アプリ内の書き込みは既存の版照合・履歴と同じ経路に合流させる。複数ファイルの同期では更新を一組として準備し、直前の照合に失敗したら差分を出し直す。書き込み中断に備え、復元に必要な版と処理の進捗を保持する。全体が確定してから新しい同期基点と履歴を公開する。途中で外部編集と競合した場合はその内容を上書きせず、復旧が必要なファイルを表示して次の同期を止める。履歴から取り消すときも現行版を照合する。

## デスクトップと組版

- R-81 では既存の「論文編集」のカード行に「TeX で編集」を置く。組版可能なカード正本のフォルダー型に限り、既存の主張または証明を一部位ずつインラインで開く。`Ctrl+Enter` で差分と検証結果を開き、確認操作で `SaveCard` の版照合付き保存を行う。`Esc` は下書きから離れる操作とし、未保存時の確認と IME 中のキーを既存動作にそろえる。カード表示と履歴が更新されるところまでをこの段階で届ける。[現行の部位編集](../../crates/fuzukue/src/paper_edit.rs) · [カード保存](../../crates/secretaire/src/cards.rs)
- 保存前は対象と部位・版・UTF-8 を確認し、静的に判定できる範囲で断片の構造を検査する。本文内の数式環境は編集できる。文書全体や構成を変える命令は、該当する編集先を示す。保存後に通常のデッキビルドを走らせ、同じ入力版の既存の自動ビルドがあれば合流する。保存とビルド結果を別々に表示する。組版失敗時も保存した TeX と前回の成功 PDF を残し、エラーやログから修正・再試行または履歴から取り消せるようにする。ビルド成功による確認と、部位の保存前検証を混同しない。
- R-34 でスレッド下の単一枠が使えるようになったら、カード編集内の「TeX で編集」と元原稿を開くテキスト表示を同じ枠につなぐ。`F2` の既定はカード編集。TeX 表示と部位タブは同じ下書きの所有者を持ち、重複する編集画面を開かない。部位・ファイルごとのカーソル、選択、下書きと「戻る」「進む」は R-34 に従う。[エディタ枠の設計](editor-pane.md) · [R-34](../../roadmap/cards/R-34.md)
- デスクトップでは既に TeX の構文表示・アウトラインがあり、汎用のソース編集と LSP のバッファ同期・補完・定義・診断を再利用できる。サーバーには texlab の既定起動がなく、実ファイルでは最寄りのワークスペース設定の `[lsp]` で `tex = "texlab"` を指定する経路を使える。対応する LSP の起動・ルートや診断の投影を確かめてから、実ファイルで補助として提供する。仮想バッファや生成コピーに実体のファイル名を偽装しない。texlab の有無にかかわらず保存でき、組版は対象ルートを使う通常のビルドに委ねる。[構文アウトライン](../../crates/fuzukue/src/source_outline.rs) · [クライアントの LSP](../../crates/fuzukue/src/source/lsp.rs) · [サーバーの LSP 設定](../../crates/secretaire/src/lsp/project.rs)
- `BuildPaper` / `BuildResult` と既存ビルドを再利用する。カードから組版するルートと `[build].tex_root` で指定した既存原稿は、入力と成果物の別の組として扱う。原稿同期では、どちらを組版したか結果に表示する。R-34 の逆引き（`LocatePdf` / `synctex edit`）で PDF から元部位や原稿へ進み、順引き（`synctex view`）で保存した位置から PDF へ移る。対応が行単位まで取れなければ部位またはファイルで開く。PDF、SyncTeX、対応表、入力版が同じ組版のものと確認できた場合だけ位置を結び、古い PDF は古い版と明示する。再掲や複数ルートでは対象成果物を選ぶ。診断が生成行を指すときは、確実に対応する元の行、またはログを開く。[ビルド](../../crates/secretaire/src/build.rs) · [PDF ビュー](../../crates/fuzukue/src/paper_pdf.rs) · [逆引き](../../crates/secretaire/src/synctex.rs) · [往復検査](../../crates/secretaire/src/pdf_audit/sync.rs)

Android の初期範囲は、R-34 のカード編集と PDF↔カードの移動。専用 TeX モード、原稿同期の適用、生成 TeX の書き戻しはデスクトップから始める。Android で対応する PDF やカードを開いたときも、表示対象と版が分かるようにする。TeX の閲覧や差分承認を Android に広げるかは利用状況を見て決める。

## 選択範囲への指示

TeX の選択に「この `align` を二行に分ける」のような一行の指示を添えてスレッドへ送る。デッキ・カード・部位または原稿のパスとアンカー、範囲、引用、版、組版ルートを渡す。生成 TeX や PDF から始めた指示は、範囲を正本に対応付けられる場合に同じ編集先を提案する。対応が取れない引用は相談に使える。対象外の箇所を変更する必要が出たら差分で明示し、適用時は手編集と同じ再検証・版照合を通す。未保存の選択から提案した場合はその下書きの版も照合し、承認した変更を下書きに取り込んで通常の保存・同期で確定する。エージェントの提案は R-12 の差分を利用者が承認してから反映する。[R-12](../../roadmap/cards/R-12.md)

## 失敗時の扱い

| 状況 | 表示と復帰 |
| --- | --- |
| 原稿の削除・移動、権限不足、ワークスペース外へのパス解決、非 UTF-8 | 対象と理由を示す。書き込みを保留し、場所や権限を直してから対応を取り直す。 |
| ラベル重複、未対応の定理、証明の対応が複数、古い対応表 | 候補または検査結果を示す。アンカーを確認し直すまで、該当範囲に基づく適用を止める。 |
| 保存・適用直前に外部エディタや別の利用者が更新 | 最新版・基点・下書きを表示する。下書きを保持し、再プレビュー後に適用する。 |
| マクロやパッケージ不足、`latexmk` が起動できない、組版エラー | 保存状態とビルド状態を表示し、診断またはログを開く。前回の成功 PDF があれば引き続き読める。 |
| SyncTeX がない、生成物の版が違う、位置の対応が取れない | 移動できる粒度と理由を示す。版違いなら再ビルドを案内し、現在の本文への推定ジャンプはしない。 |

## 未決事項

- デッキ文書の書き出し基点、原本同期の対応表・復元可能な基点をデッキ内で共有するか、履歴に持たせるか。共同編集者が再現できること、古い基点の保持期間、既存デッキの移行コストを比べる。
- ラベルを持たない既存の定理・解説に、利用者が範囲を指定して安定したアンカーを付ける方法。原稿に手を入れられない場合の照合範囲も決める。
- 章構成や共有プリアンブルの同期をどこまで自動提案するか。同じ入力が複数ルートに現れる場合の既定の成果物と、確認対象のビルド数を決める。
- Android で必要な TeX 閲覧と差分表示の範囲。共同編集者がスマートフォンから承認する必要があるか確かめる。
