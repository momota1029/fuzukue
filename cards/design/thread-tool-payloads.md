## 保存と表示

スレッドの Markdown には会話本文、ツールの項目 ID、状態、プレビューを置く。出力が 1 KiB を超える場合と、入力の JSON が 4 KiB を超える場合は、全文を SHA-256 で引けるファイルに保存する。通常ツールの出力プレビューは、省略記号を含めて 256 バイト以内に先頭と末尾を残す。古いプレビューも読み込み時に同じ上限に収める。委譲ジョブの報告は構造を持つため、報告本文と変更の説明をそれぞれ短縮し、状態に必要なフィールドを残す。入力の頻出フィールドと、委譲ジョブの状態に必要なメタデータはプレビューからも読める。Markdown とジャーナルの参照を公開する前に、ペイロードのファイルとディレクトリを同期する。

Desktop と Android はプロトコル 75 の `GetThreadToolDetails` を使って、開いたツール 1 件の全文を読む。通常の履歴やライブ配信は従来と同じツールイベントでプレビューを送る。古いクライアントもこの形を読める。委譲ジョブの詳細を開いたときは最終報告を取得でき、子ツールの全文はそれぞれの詳細から取得する。応答が WebSocket の 12 MiB 上限を超えた場合は、元のリクエスト ID を持つ取得失敗を返し、読み込み状態を解除する。

`threads/.fuzukue-thread-save/payloads/` は既存の非公開保存領域に含まれる。Git、履歴・ライブラリの索引、ワークスペースの汎用ファイル閲覧から除外する。Markdown と保存領域を一緒に持ち運ぶと、ファイルへ分離済みの全文も移動できる。Markdown 単体のコピーには会話本文とプレビューが含まれる。旧ジャーナルにしかない全文の移動には、そのジャーナルも必要になる。

## 既存ファイルの変換

起動から独立したアイドル処理で、1 スレッドずつ扱う。空き容量を先に確認し、原本と置換ファイルを同じファイルシステムに作る。元の UTF-8 出力と入力の JSON バイト列を、保存した各ファイルから読み戻して照合する。原本のコピーは、元のバイト列と別個に読み直した SHA-256 が一致したときだけ採用する。

原本の確定と同期を済ませ、ライブファイルの SHA-256 を Hub と保存ディレクトリのロックを取る前に照合する。ハッシュの計算前後で、開いているファイルと現在のパスのデバイス番号、inode、サイズ、mtime、ctime を確認する。Hub のロック下で稼働状態と既知の世代を確かめ、従来のサーバーと共用する保存ロック下でファイルの属性をもう一度照合してアトミック交換する。差があれば公開を中止する。照合と交換の間に外部の書き手がファイルを差し替えた場合は、交換で押し出されたファイルを保持する。交換後のディレクトリ同期は両方のロックを解放してから行う。再試行では既存の原本とペイロードを照合して再利用する。原本は通常の前世代ファイルと別に保持し、自動削除しない。

## 旧版での保存と再アップグレード

ペイロードの SHA-256 は、通常の `payloads` 欄に加え、同じ項目の `attachments` 欄に予約済みの形式で記録する。ツール項目に付けたこの記録は `32dc4e7` の保存処理も保持し、添付ファイルとして表示しない。再アップグレード時は項目内の参照からペイロードを照合して復元する。参照があってファイルが欠けている場合や照合に失敗した場合は、残っているプレビューを表示し、全文は取得不可とする。参照付きのプレビューを新しい原本として登録することはない。

`32dc4e7` は `preview_payloads` と `payloads` を落とし、通常のツールではインラインの入出力も落とす。保存領域があれば、大きな通常ツールの入出力と大きな委譲ツールの入出力は項目内の参照から回復する。小さな委譲ツールの入出力は旧版の Markdown に残る。参照のない小さな通常ツールの入出力は、旧ジャーナルがなければ自動では戻らない。変換前の原本に含まれていれば、その原本から取り出せる。

合成した通常ツールと委譲ツールを大小 1 件ずつ用意し、変換版、実際の `32dc4e7` の読み込みとタイトル変更保存、再アップグレードの順に通した。旧版の保存で通常ツール 2 件の入出力欄が消えた。再アップグレードで大きな通常ツールと委譲ツールの全文、小さな委譲ツールの入出力、旧版で変更したタイトルを復元できた。小さな通常ツール 1 件の入力と出力は取得不可になり、プレビューから作ったサイドカーは 0 件だった。

## 検索、引き継ぎ、復旧

会話検索と、会話の抜粋を使う引き継ぎは、引き続き会話本文を読む。Markdown をエクスポートするとツール欄にはプレビューが含まれる。変換前の全文が必要な場合は保存した原本を使う。既存のジャーナルはそのまま保持する。復旧では旧レコードを一件ずつ読み、プレビューと読み戻し位置を保持する。古いジャーナルに同じツールの記録があっても、保存済みのサイドカー参照を残す。変換後に旧ジャーナルを残して再起動し、通常保存したうえでジャーナルなしで開いても全文を復元できる。大きな旧ジャーナルを初めて開く際には走査が必要になる。キャッシュは、メモリ上の項目とプレビューの推定サイズを 24 MiB の目安に収める。直近に使用したスレッド 1 件は、この目安を単独で超えてもアイドル期限まで保持する。

作業役の成果物パスと失敗出力の末尾は、ライブイベントの全文からプレビュー作成前に抽出する。既存の記録からの成果物復旧は、起動処理を待たせず、成果物を開いたときか後続のアイドル処理で行う。

新しいジャーナルにはプレビューと参照を追記する。サイドカーへの書き込みに失敗したらジャーナルに全文を追記し、両方に失敗したら全文をメモリに保持する。アイドル処理は未保存スレッドを再試行し、メモリにしかない全文を持つスレッドは稼働中でも再試行する。通常の終了と自己更新では、作業を受け付けなくなったあとに未保存のスレッドを期限つきで保存する。保存に失敗している間は更新を開始せず、終了時の最終再試行にも失敗した場合はエラーを報告して非ゼロで終了する。Markdown の交換後にディレクトリの同期が失敗しても未保存の状態を保ち、次の試行ではその交換で作った世代から保存をやり直す。

変換済みスレッドの保存では、ジャーナルにしかない全文をサイドカーに移してから Markdown を更新する。変換中に未保存の新しいツール結果を受け取っていた場合も同じ手順を使う。メモリにしかない全文は、サイドカーにまだ書けなくても Markdown に書ける場合はそこで保全する。再起動時は、保全した記録より前に同じローカルジャーナルに書かれた同一ツールの入出力を上書きに使わない。

通常保存では Markdown 全体を置き換える。置換対象を会話本文とプレビューに縮め、前世代のハードリンクを使う既存の保存手順を維持する。変換直後のディスク使用量には原本、プレビュー版、ペイロードが含まれる。

## 前回の合成データでの計測

`32dc4e7` と変更版で、2,048 件の固有のツール記録を持つ同じ合成スレッドを読み込み、タイトルを変更して通常保存した。デバッグ情報とインクリメンタルビルドを無効にした Linux のテストバイナリで 1 回ずつ測定した。ヒープは `malloc_trim(0)` のあとに `mallinfo2` の使用中アリーナと mmap 領域を足し、読み込み前からトランスクリプトを保持した時点までの増分を取った値。既存の大型ジャーナルはこの測定に含めていない。

| 項目 | 32dc4e7 | 変更版 |
| --- | ---: | ---: |
| Markdown | 310,796,950 B | 5,389,398 B |
| 読み込み後のライブヒープ増分 | 312,934,672 B | 7,563,344 B |
| 読み込み | 1,217 ms | 35 ms |
| 通常保存 | 4,881 ms | 145 ms |

初回変換は 41.89 秒。変換前の原本は 310,819,559 B。原本と計測開始時のファイルサイズの差は、基準版で行ったタイトル変更とその保存による。

## 33,000 件の合成データでの計測

Linux のデバッグ情報なし、インクリメンタルビルドなしのテストバイナリで、異なる大きな出力 33,000 件を持つ Markdown を変換した。ジャーナルは空で、同じスレッドの同じツールを 20 回照会した。キャッシュサイズは、24 MiB の予算判定で使うトランスクリプトの推定値。

| 項目 | 計測値 |
| --- | ---: |
| 変換前の Markdown | 320,330,728 B |
| 変換後の Markdown | 19,491,971 B |
| キャッシュサイズ | 42,207,000 B |
| 初回後の再読み込み | 0 回（計 20 回照会） |
| 初回の読み込みと照会 | 255.04 ms |
| キャッシュ済みの照会（19 回の平均） | 3.28 µs |
| Hub ロック内の公開処理（保存ロックを含む） | 4.13 ms |
| 公開後のロック外ディレクトリ同期 | 5.25 ms |
| 従来はロック内にあったライブファイルの SHA-256 照合に相当する単独計測 | 4.05 秒 |
| 公開前のステージング全体 | 614.24 秒 |

直近 1 件を保持するため、推定値が 24 MiB を超えても連続照会のたびに読み込むことはない。公開の計測は稼働中のスレッドがない状態で、Hub ロック下の公開関数の開始から返却までを測った。4.05 秒は同じファイルを直前に読み込んだ状態でのハッシュ計算だけの時間で、旧実装のロック保持全体は計測していない。ステージングの計測中は別の合成データ変換やテストと一部並行した。

```sh
cargo test -p secretaire measure_large_thread_publication_and_cache -- --ignored --nocapture
```
