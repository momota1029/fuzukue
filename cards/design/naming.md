2026-11-21、利用者の決定「fuzukueにしよう、サーバーはセクレテールで」。

- アプリ全体とクライアントは **fuzukue**。文机は、床に座って読み書きするための低い机。
- サーバーは **secretaire**。フランス語の *secrétaire* は収納の付いた書き物机を指し、秘書の意味もある。エージェントが働く側の名前にした。
- ライブラリと WIT の名前空間、MCP のサーバー名、引き継ぎスキル、環境変数は `fuzukue` にそろえる。専用ブランチの設計上の既定は `fuzukue/ops`。
- `FUZUKUE_*` が未設定なら `LABO_*` を読み、変数ごとにプロセス内で初回だけ移行を案内する。利用者の設定と起動スクリプトが切り替わったら旧名を廃止できる。
- 新しい設定・状態ディレクトリがなければ、旧 `labo-gui` ディレクトリを `fuzukue` に改名する。別ファイルシステムなら一時ディレクトリにコピーしてから切り替え、元データと案内の README を残す。両方あるときは新しい方を使う。
- ワークスペースは `fuzukue.toml` を優先し、両方ある場合は警告する。なければ `labo.toml` を読む。隠しディレクトリは新しい `.fuzukue/` を優先して旧 `.labo/` も読み、新規データは `.fuzukue/` に置く。GitHub の投稿は `<!-- fuzukue -->` を付け、旧マーカーも自分の投稿として扱う。
- 配布 URL と版の形式は維持する。旧クライアントは更新を元の exe の位置に置き、新版は起動確認後に `fuzukue.exe` を同じ場所に作る。旧ショートカットの移行が済んだら旧ファイル名での起動対応を終えられる。新旧サーバーの入れ替えでは起動確認と直前の版への復帰を維持する。

実機での手順は [更新ガイド](../../docs/update.md#旧版から名前が変わる最初の更新) にまとめた。
