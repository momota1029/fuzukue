> コメント含めて人が読めるLeanハーネスみたいなのあると良いのでは
> 文芸的Leanプロジェクトです

作業役に Lean の証明を任せると、機械が確かめられるのは「`sorry` がない」「標準の公理だけ」まで。主張が意図どおりか、証明が何をしているかは人が読むしかない。そこを読みやすくする。

考え方は文芸的プログラミング: 読み物（散文の説明と数式）が主で、Lean はその中に埋め込まれた、機械が確かめる部分。人は上から読めば筋が分かり、機械は同じファイルから証明を検査する。

## 文芸的 Lean の形

- 正本は `.lean` ファイル。節は module doc（`/-! … -/`）で書き、見出し・説明・数式を置く。定理ごとの doc コメント（`/-- … -/`）と、証明の中の `--` の筋が続く。Lean がそのまま読めるので、ビルドと検査の仕組みは今のまま。
- fuzukue はこれを「読み物」として表示する: module doc を本文に、宣言を本文の中の枠に、証明は筋だけを見せて畳む。各段のゴールは LSP から取って横に添える（Alectryon や LeanInk のように、読みながらゴールが見える形）。
- 論文のデッキとの関係: カード（TeX）は論文の主張、文芸的 Lean は形式化の読み物。カードの `lean:` と Lean 側の `-- card:` で行き来する。論文から形式化を、形式化から論文を、同じ画面で開ける。
- 書き出し: 読み物を HTML か PDF に書き出せる（ゴール付き）。共同研究者や査読者に渡せる形。

## 既にあるもの（形は作らず、合わせる）

- **Verso**（Lean 公式の執筆道具）: 文芸的モードがあり、Verso 形式の doc コメントを含む Lean のファイルを、そのまま Web ページにする（`literate.toml` で並びと題を決める）。開発が速く、形はまだ変わりうる。
- **Lean Blueprint**: TeX の設計図の各命題に `\lean{宣言名}` と `\leanok` を付け、形式化の進み具合と依存のグラフを出す。カードの `lean:` と状態の表示はこれと同じ考え。
- **LiterateLean**（第三者のパッケージ）: Lean ファイルの中に Markdown 風の散文を書き、```` ```lean ```` の部分だけを実行する。

方針: 独自の書式は作らない。書き方は Verso の文芸的モードの決まりに合わせ、同じファイルを Verso でも書き出せるようにする。カードと宣言の対応は Blueprint の考えに合わせる。fuzukue が受け持つのは、読む画面、ゴールの表示、取り込み時の主張の確認、作業役への決まりの配布。

## 書く側の決まり（作業役へのルール）

- 定理・定義・構造には必ず doc コメント（`/-- … -/`）を付け、何を主張するかを自然な文で書く（数式は `$…$`）。論文のカードに対応するものは `-- card: <id>` を添える（カードの `lean:` と両方向）。
- 証明は、山場ごとに `--` で筋を書く（「帰納法で n について」「ここで補題 X を使って長さをそろえる」）。数行で終わる証明は不要。
- 主張を変えたときは、doc コメントも同じコミットで直す。
- 決まりは Lean 用のルールパック（スキル）として作業役に渡し、Lean の査読役（`reviewers/lean.md`）が「doc コメントと主張が食い違っていないか」「筋のコメントが証明と合っているか」を見る。doc コメントのない公開の定理は、査読の指摘にする。

## 読む画面

- **宣言のカード**: 一つの定理を、カードのように開く。
  - 上に doc コメント（Markdown と数式として表示）。
  - 主張: 仮定と結論を分けて並べる（`(h : …)` を一行ずつ、結論を最後に太く）。暗黙の引数と型クラスは畳む。
  - 対応する論文のカードの主張を横に並べ、人が見比べられるようにする。
  - 状態（証明済み・`sorry` あり・ほかの公理）と、使っている補題・使われている所。
- **証明の筋**: `--` のコメントを見出しにして、間のタクティクは畳む。見出しを押すと、そこのゴール（LSP の `lean_goal`）を表示する。前後のゴールの差分を出して、何が進んだかを見せる。
- **ファイルの一覧**: ファイル内の宣言を doc コメントの一行目と状態で並べる（アウトラインの Lean 版）。

## 取り込むときの確認（[[branch-review]]）

- Lean のファイルを変えたブランチでは、差分の前に「主張の変化」を出す。追加・変更された定理ごとに、doc コメント、主張の前後、対応するカードを並べる。
- 人が「主張を確かめた」を押した記録を残す（誰が、いつ、どの版を）。確かめていない主張の変化があると、取り込むときに警告する。
- 証明の中身だけが変わり、主張が変わっていないものは、まとめて一行にする（機械の確認で足りる）。

## 段階

1. 書く側の決まり（ルールパックと査読役の指示）と、doc コメントのない定理の検出。
2. 宣言のカードと、ファイルの一覧（tree-sitter と LSP の記号で作る）。
3. 取り込み待ちの「主張の変化」と、確かめた記録。
4. 証明の筋とゴールを含む読み物の HTML 書き出し。

## 実装

1. 作業役には Lean パッケージのある作業場所と Lean の依頼で `literate-lean` スキルを渡す。同名のスキルは既存のルールパックの優先順で上書きできる。Lean 査読は doc コメントと主張、段のコメントと証明を照合する。Lean 状態と `lean_doc_check` は公開宣言の doc コメントの欠落を返し、作業ツリーを基準との共通祖先と比較して定理の主張だけ変わった箇所を指摘する。
2. プロトコル 39 で、Lean のソースから「読み物」に切り替えられる。宣言の構造とコメントは同梱の tree-sitter 文法で取り、`mutual` は解析時だけ `section` として読む。カードの `lean:` と記号検索から宣言へ開ける。読み物は論文と同じ Markdown・数式表示を使い、仮定、結論、カードの主張、監査済みの公理依存、記号索引上の依存関係を見られる。段を開くと、その段のタクティクの先頭と末尾を `$/lean/plainGoal` に問い合わせて差分を出す。ページ内の順序はソース順とし、Verso 全体の並びと題は既存の `literate.toml` に置く。
3. 取り込み待ちは Git の共通祖先と作業ブランチにある宣言を比較する。「主張の変化」に前後の署名と doc コメント、関連カードを載せ、証明だけ変わった宣言は件数を表示する。確認者の Git の識別情報、時刻、基準側と作業側のコミットをサーバーに保存する。未確認の主張や解析できない Lean の差分がある場合は、取り込みの確認画面で個別に承認を求める。
4. 「書き出す」は、表示中のファイルか選んだ宣言を一つの HTML に保存する。段ごとのゴールは書き出し時に取り直し、タクティクと差分を開閉できる形で埋め込む。数式に使う KaTeX は版を固定し、取得できない場合は TeX を表示する。
