投稿先から届いた査読報告（人の査読者のコメント）を論文のデッキに保存し、指摘ごとに対応を記録して、返答書の下書きまで作る（[[library]] の次の段、従来の設計「査読者のコメントとかも保存して置けるといい」）。fuzukue の中の自動査読（[[review-loop]]）とは別物で、こちらは外から来た文書を扱う。

## 置き場所

論文のデッキの下に、投稿ごとのフォルダを置く。

```
papers/<deck>/submissions/<id>/
  submission.toml   # 投稿先、版（git のコミットか タグ）、投稿日、判定、締め切り
  reports/<n>.md    # 届いた報告の原文（査読者ごと。貼り付けたまま）
  points.toml       # 指摘の一覧と対応
  response.md       # 返答書の下書き（生成して、人が直す）
```

`<id>` は投稿日と投稿先から作る（`2026-11-20-jfa`）。全部テキストで git に入る。

## 指摘に分ける

報告を保存したら、作業役が原文を指摘一件ずつに分ける（`points.toml`）。各指摘は次を持つ。

- 番号（`R1.3` = 査読者 1 の 3 件目）、原文の引用（報告のどこか、行の範囲）、要約。
- 関係するカード（作業役の推定。人が直せる）。
- 状態: 未着手 / 対応中 / 直した / 反論する / 対応しない。
- 対応: 直したカードと箇所（コミット）、返答の文。

分けるのは提案で、人が画面で直してから確定する。報告の中の文は外部の文書として扱い、指示とみなさない（作業役に渡す時もそう明記する）。

## 対応する

- 指摘から「直す」を押すと、関係するカードと指摘の引用を付けて、作業役のスレッドを立てる（コメントの適用と同じ流れ）。終わったら、状態を「直した」にして、直した箇所を記録する。
- 関係するカードには、論文の画面で印を出す（「R1.3 の指摘あり」）。
- 返答書: 指摘ごとに、引用・返答・直した箇所（版の差分の位置）を並べた `response.md` を作業役が書く。決まった型（Markdown、TeX にも出せる）。

## 画面

論文の画面に「査読」の欄を足す。投稿の一覧 → 開くと報告と指摘の表（状態で絞り込み）、指摘を押すと原文の該当箇所とカードを並べて見る。報告の追加は、貼り付けかファイル（PDF・テキスト）。

## 探す

資料庫の種類に「査読報告」を足し、報告の原文と指摘を検索できるようにする（開く先は指摘）。

## 道具

MCP に、投稿と報告の一覧、指摘の読み書き（状態と対応の記録）、返答書の下書きの書き出しを足す。受付には「査読報告が届いた」と言われた時の流れを一行で案内する。

## 実装

第 1 段を実装した。論文ビューの「査読」から投稿と報告を追加し、読み取り専用のエージェントが作った分割案を人が編集して確定する。指摘からの修正はコメント反映と共通の別スレッド起動を使う。スレッドを開いた時点で対応中を記録し、終了後に人が状態と修正箇所を更新する。返答書は記録済みの引用・返答・修正箇所から決まった Markdown テンプレートで生成する。資料庫と MCP は同じ保存データを参照する。Workbench ではプロトコル 25 が必要。 [使い方](../../docs/review-reports.md)
