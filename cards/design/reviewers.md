> 「あとは本当にAIっぽい言い回しや悪文を防ぐための汎用的文体ハーネスを用意して，敵対的文体査読エージェント，Lean査読エージェントなんかを別で起動するのがいいかもしれませんね．」

## 査読を起動する

WebSocket は `RequestReview { deck, kind }` を受ける。MCP の `request_review` は `kind` に `style`、`lean`、`math` を取り、デッキを省略すると表示中のデッキを使う。処理はバックグラウンドで動き、MCP はセッション名をすぐに返す。

節を査読するときは MCP の `request_review` に順序つきの `cards` と `kind: "math"`、`"output"`、または `"both"` を渡す。応答の `reviews` に査読ごとのセッションを返す。 [節の査読と記録](../../docs/lecture-notes.md#4-数学出力の確認の依頼と記録)

`consistency` は人の編集を閉じたときに起動する。編集差分と同じデッキ内の参照先を読み、指摘を `[人の編集] [整合]` 付きの下書きにする。詳しくは [[human-edits|整合確認]]を参照。

文章査読は Claude Code の一回限りのセッションで実行する。既定は Claude CLI のモデル設定に従い、
ツールは Read、Grep、Glob に限定する。Lean と数学の査読は独立した Codex スレッドで実行し、
既定は `gpt-6.2-sol`、思考レベルは `medium` とする。Codex のサンドボックスは
`read-only`、承認ポリシーは `never` とする。
WebSocket の v13 は `ReviewStatus` にモデル、開始時刻、完了時の件数と移動先のカードを含める。

## 読むものと返すもの

- 文体査読は `structure.yaml` の順に、カードの主張、証明、ノートを読む。定型の表現、悪文、未定義語、説明の飛躍、記号の不一致を見つけ、原文を正確に引用して修正案を出す。
- Lean 査読は `lean:` のあるカードの主張と実際の宣言を突き合わせる。論文の並びに含まれないローカルカードも、宣言があれば調べる。サーバーが最後に取得した Lean の状態を受け取り、`sorry`、非標準公理、仮定や結論の食い違い、形式化の抜けを、カード ID と宣言名を添えて指摘する。状態を取得していない宣言は `unchecked` として渡す。
- 数学査読は主張と証明を照合し、仮定の不足、推論の抜け、反例を調べる。
- 査読への指示は `reviewers/style.md`、`reviewers/lean.md`、`reviewers/math.md` に置く。サーバーはビルド時に既定の指示を取り込み、プロジェクトの根に同じ相対パスのファイルがあればそちらを使う。
- 査読の返答は `{"findings":[{"card":"<ID>","text":"<引用、指摘、修正案>"}]}` とする。サーバーは JSON のコードフェンスも受け付ける。

## 下書きから会話へ

サーバーは指摘に `[文体査読]`、`[Lean 査読]`、`[数学査読]` を付け、デッキの `.fuzukue/comments.json` に追記して `Comments` を配る。デッキにないカードへの指摘は除外し、その ID を最初のカードに一件の下書きで知らせる。JSON を読めなかった場合は、最初のカードに理由と返答の末尾を残す。

査読の完了行から、論文エディタのコメント下書きを開ける。下書きを確認して反映用の別スレッドに送れる。

## 原稿しか読めない査読者（2026-11-20、ユーザー）

>「あとは査読の仕組みもMCPを制限してファイルを読めなくしたエージェントに対応させられると思うので、そういうハーネスも組みたいね」

案:
- 査読者は、プロジェクトのファイルを直接読めない。ファイル読み取り・検索・シェル・Web の道具を外し、空の作業ディレクトリで動かす（Claude は組み込みの道具を止めて、査読用の MCP の道具だけを許す。Codex は読み取り専用・ネットワークなし・空のディレクトリで、シェルを止める）。
- 読めるのは、査読用の MCP の道具が渡すものだけ:
  - 投稿する形の原稿（組み上げた PDF の本文、節・定理・式の番号付き。カードの ID やメモ、作者向けの注は見せない）。
  - 原稿の中の検索、節や定理の単位での読み出し。
  - 引用文献の書誌情報（と、取得してあれば要旨）。
  - 報告の提出（要約、主な指摘、細かい指摘、質問、判定。指摘は原稿の場所に付ける）。
- これで、作者のメモ、前の版、AI との会話、Lean のファイルなどを見ずに、原稿だけで成り立っているかを確かめられる（実際の査読者と同じ条件）。
- 査読者の種類: 原稿だけの査読者、引用文献も見られる査読者、数学の確認役（原稿だけで証明を追う）、編集者役（複数の査読報告を読んで判定をまとめる。報告以外は読めない）。どれもモデルは設定で選ぶ。
- 報告は査読の回ごとに保存し（従来の設計の「査読者のコメント」と同じ置き場所）、指摘をカードのコメント下書きに変える（今の仕組みを使う）。
