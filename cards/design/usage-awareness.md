- サーバーが使用量を集める。Claude は stream-json の `rate_limit_event`、Codex は app-server のレート制限の通知。
  5 時間枠・週枠・セッション単位（部分）と、全体（全セッション合計）を持つ。
- クライアントはステータスバーに常に表示する。人が見るのはここ。
- エージェントには、ターンの頭に短い隠し文脈として残量を渡し、「計画には使う。計画を変えるとき（止める、分ける、
  安いモデルに回す）だけ口にする」と指示する。
- 今の usage-limits フックは毎ターン発話を強いるので、サーバーが起動するエージェントでは切る（[[hook-leak]]）。

作業は利用量の制限を考慮し、進行に影響するときに知らせる。

決定（2026-11-19、ユーザー）: この提案について「正直それでいいと思います」

休憩と再開（2026-11-19、ユーザー）:「長時間作業をするときに5時間制限がきそうになったら休む（リセットされたら自動的に再開する）という仕組みが欲しい」

実装（2026-11-19）:
- 閾値は `FUZUKUE_PAUSE_AT`（既定 0.95）。ある agent のどれかの枠が閾値を超えたら休む。複数の枠が超えていれば、一番遅いリセットまで待つ。
- Claude: ターンの途中で `rate_limit_event` が閾値を超えたら、`control_request` の interrupt で止める（プロセスと会話は残る）。
  レート制限のエラーで止まったときも休む（リセット時刻が分からなければ 15 分）。
- 休憩中のユーザーのメッセージはためる。リセット時刻の 30 秒後に、「中断したところから続けて」とためたメッセージをまとめて送る。
  その時点でまだ枠が空いていなければ休み直す。クライアントの「今すぐ再開」で待たずに再開できる。
- Codex: 枠を超えていれば `codex_run` は断り、Claude に「Codex に回さずに進めて」と返す。
- 使用量メモは、Claude にも Codex にもメッセージの前に付ける。方針はシステムプロンプト（Claude は `--append-system-prompt`、Codex は `developerInstructions`）。
- 確かめた: 閾値 0 で、途中での割り込み → 休憩 → ためたメッセージ → 今すぐ再開 → 中断した作業の続き。
- 確かめていない: 本物のリセット時刻を待っての自動再開。

## 方針と作業の段階

- 全力・ふつう・節約で同時実行数と開始間隔を調整する。節約、または候補の使用枠が 90% に達したときは、一段下げる。`min_tier` を下回らない。
- 使用枠で候補を使えなければ、同じ段階に設定された使える候補を選ぶ。スレッドで実行先を指定した仕事ではその指定を優先する。
- 受付のモデルは固定する。使用枠で止めた長期目標は、枠が戻ると再開する。段階と切り替えの理由は詳細で見られる（[[tiers]]）。
