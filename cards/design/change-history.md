作業役に本物の原稿を任せる時の一番の不安は「勝手に壊されたら」。カードとファイルの変更を、誰が（人か、どの作業役か、どのスレッドか）、いつ、何を変えたかで残し、一つずつ戻せるようにする。

## 記録

- 変更の単位は「一回の保存」と「作業役の一回の仕事（ターン）」。作業役のターンが終わった時に、そのターンで変わったファイルをまとめて一つの記録にする。人の保存（`save_card`、`save_file`、ソースエディタ）は保存ごとに一つ。
- 中身は git に任せる: プロジェクトのリポジトリとは別の、影の git（サーバーの状態フォルダの `history.git`、作業ツリーはプロジェクト）にコミットする。利用者のブランチや履歴は汚さない。`.gitignore` に従い、ビルド出力は入れない。
- 各記録は: 誰が（`human`、`agent:<名前>`、`reviewer:<種類>`、`extension:<名前>`）、スレッド、ターン、日時、変わったファイル、ひと言の要約（作業役の最後の発言から）。
- 作業役のターンの前にも、その時点の状態を記録しておく（人の未保存の編集と混ざらないように、ターンの直前と直後の差を作業役の変更とする）。

## 見る

- カードの画面に「履歴」: そのカードの変更の一覧（誰が・いつ・要約）と、押すと差分。
- スレッドの作業役の発言に「この仕事の変更」: そのターンで変わったファイルと差分。
- 情報欄に、最近の変更の一覧（全体）。

## 戻す

- 一つの記録を戻す: その記録の差分を逆に当てる。後の変更とぶつかる所があれば、ぶつかった所を見せて、戻せる所だけ戻すか、やめるかを選ぶ。
- カードを、ある時点の状態に戻す。
- 戻したこと自体も一つの記録になる（戻したのを戻せる）。
- 作業役の道具からは戻せない（人だけ）。

## 残す量

- 既定は 90 日、または 2,000 記録まで。古いものは影の git の gc で畳む。設定で変えられる。

## 実装

プロトコル 29 で実装した。状態ディレクトリの `history.git` に、変更ファイルだけを含む前後のコミットを一組ずつ置き、記録のメタデータは後側のコミットメッセージに JSON で保存する。カードの履歴、会話のターン、情報欄から差分を開ける。戻す際は作業ツリーへの適用前に競合を調べ、利用者が選んだ場合だけ競合のない箇所を戻す。カードの復元先は選択した記録の直後となる。

利用者の保存と拡張の書き込みは、ターンのスナップショットから取り除く。同じファイルが作業中に変更されたあとで利用者が保存すると、そのパスには書き手を分離できない部分があるため、ターン側からそのパスを外す。保存期間の設定と監視範囲は [docs/history.md](../../docs/history.md) を参照。
