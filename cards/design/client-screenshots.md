離れたサーバーに接続している作業台の表示を、そのまま相談や不具合報告に添えられるようにする。撮る範囲は作業台のウィンドウ。

## 利用者から撮る

Ctrl+Shift+S、検索パレットか左の「その他」の「画面を撮る」、または入力欄の「＋」にあるカメラから始める。メニューを閉じたフレームを表示してから撮る。Windows は HWND とプロセス ID で自分のウィンドウを特定し、Windows Graphics Capture で描画を取る。Linux の X11 は ImageMagick の `import` を使う。Wayland ネイティブと macOS は未対応。

プレビューに必要ならメモを書き、送り先を決める。送信する PNG が 4 MiB を超える時は縮小する。

- **入力欄に添付**: PNG を通常の添付と同じ経路でワークスペースの inbox に送り、作成欄に追加する。メモは作成欄の末尾に入る。利用者が発言を送った時、受付にはファイルの情報と画像入力が届く。
- **メモに残す**: `memos/<id>/` にメモのカードと `screenshot.png` を置く。カードから画像を相対リンクで参照する。
- **不具合として報告**: GitHub の報告ダイアログを開き、送信先・題名・メモを含む本文・画面写真を表示する。アプリからは題名と本文を送る。画像を添える場合は PNG を端末に保存し、ブラウザーで GitHub の Issue に添付する。

従来のクライアントから届く dogfood 保存要求には、ワークスペースの `fuzukue.toml` の設定を使う。

```toml
[dogfood]
report_dir = ".fuzukue/dogfood"
# github_repo = "owner/repository"
```

`report_dir` はワークスペース相対のディレクトリ。 `github_repo` を設定すると、ローカルの報告保存後にサーバーが `gh` で Issue を作る。Issue の本文にはメモとワークスペース内の画像パスが入る。画像ファイルはワークスペースに残り、Issue 作成に失敗してもローカルの報告は残る。

## 受付・作業役から頼む

接続中のクライアントから始めたスレッドの作業で、受付または作業役は引数なしの `client_screenshot` を使える。プロトコル 37 の発言元の接続にだけ依頼を送る。別の端末への転送や再接続後の再送はしない。

依頼を受けた作業台に「受付が画面を見たいと言っています」と許可・拒否を表示する。設定の「毎回確認しない」は既定でオフ。オンの端末は依頼を受けると撮る。許可後の PNG は MCP の画像として返し、サーバーのワークスペース状態ディレクトリの `screenshots/` にも日時付きで置く。拒否、切断、未対応環境、60 秒の期限切れはツールのエラーになる。
