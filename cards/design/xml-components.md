## 描画と操作

- `fuzukue-view::ui_kit` の部品ツリーを共通モデルとし、デスクトップはこのツリーから GPUI 要素を描く。カード、グリッド、統計、進捗、バッジ、リスト、手順、折りたたみ、区切り線、キー名、インラインコードを、既存のコールアウト・表・指摘参照と組み合わせられる。
- 子を並べる順序は共通モデルに格納する。グリッドは自分の幅に合わせて狭いときは 1 列にし、トーンはテーマのトークンから引く。指摘は開いているデッキの既存スナップショットから読む。
- 部品の本文はリテラルテキストを基本とし、HTML、リンク、画像、スクリプト、ネットワークアクセスを表示経路に持たせない。チェックリストは状態表示で、折りたたみの開閉はクライアント内の操作とする。サーバーに届く操作を将来加える場合は、既存のツール承認経路を使う。

## 記法と互換性

- `~~~fuzukue-v1` の Markdown フェンスに `fuzukue:` 名前空間の XML を一要素置く。従来の接頭辞なしの `callout`、`table`、`finding` も受理する。フェンスなら名前空間付きの開始タグが Markdown の自動リンクになるのを防げる。サーバーと履歴は元の記述を運び、旧版や Android は同じ本文をコードとして表示する。
- `Hello.markdown_components` はタグのローカル名とスキーマ版の組の一覧とし、省略時は空とする。Android は省略する。意味や属性の互換性を壊す変更では、変更したタグと対応フェンスの版を追加する。未知のタグ・版・属性や、明示したサイズ・階層の上限を超える入力は、元のコードブロックにフォールバックする。
- 受信中は閉じフェンスの行末が確定するまでコードとして表示する。行が確定し、内容を解釈できた時点で部品に切り替える。

## JSON と今後の MCP 経路

- [JSON Schema](../../docs/ui-kit.schema.json) を公開し、XML と JSON を同じ部品ツリーに変換して同じ制約で検証する。
- フェンス付き XML は会話の文章に織り込め、コピーやエクスポートでも原文を保てる。将来の `ui_render` は、JSON の検証エラーをエージェントへすぐ返し、妥当な部品をタイムラインに保存して安定した ID で更新する。Markdown の解析を経由しないため、自動リンクと競合しない。 [R-51](../../roadmap/cards/R-51.md)

## アクセシビリティ

- コールアウトは種類、タイトル、本文の順で表示する。表は見出し行から最後の行まで、各行の先頭セルから順に読む。進捗は数値、チェックリストと手順は状態を読み上げ用の情報として渡す。
- 折りたたみの見出しは開閉状態を持つボタンとし、Tab で移動して Enter と Space で操作できる。
