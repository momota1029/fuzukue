Markdown 本文に既存のビューを差し込む設計案。Markdown 内での部品の解釈・描画、操作の接続、対応タグの通知はいずれも未実装。

## 描画と操作

- Markdown に埋め込めるタグは固定の小さな語彙に絞り、タグごとに GPUI の要素を対応づける。部品の記述にスクリプト実行やネットワークアクセスは持たせない。
- 表示データはインラインに埋め込まず、カード ID や MCP ツールの結果への参照で渡す。
- ボタンは対応づけたツール呼び出しを要求し、実行前に既存の承認経路を通す。たとえば「指摘を台帳に登録する」を押すと、指摘台帳への登録を承認に出す。

## クライアントの互換性

- クライアントは接続時の `Hello` に capability として対応タグの一覧を載せる。サーバーは接続ごとに一覧を見て出力を選び、一覧が届かない接続は対応タグなしとして扱う。
- 認識できないタグは、元の記述をそのまま読めるプレーンなコードブロックに落とす。サーバーも未対応の接続にはコードブロックで渡し、従来の Markdown 表示で読めるようにする。
- Android は独自のレンダラーが必要。初期は未対応タグをテキストとして表示し、対応する部品を後から Compose で描く。

## 最初の部品

既存の GPUI ビューを再利用する。

- レビュー指摘台帳（review findings）
- 探索ツリー
- 差分
- 表
- コールアウト（注記の囲み）

## 未決

- タグの記法は XML タグとフェンス付きコードブロックのどちらにするか。
- タグの意味や属性を変更するとき、語彙の版と互換性をどう扱うか。
- スクリーンリーダー向けの名前や読み上げ順、キーボードでのフォーカスと操作をどう扱うか。
- ストリーミング中にタグの一部だけが届いたとき、受信途中と閉じタグが届いた時点でどう描画するか。
