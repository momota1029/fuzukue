2026-11-24 の方針をまとめた設計案。論文や本は普段カードで受け渡しし、カードを直す。PDF はデッキから組版した閲覧用の成果物とする。

## スレッドとエディタ

通常のエディタ枠はスレッドの下に置く。開けるエディタは一度に一つ。カードのその場編集を始めるときは、同じコンポーネントをカードの位置に出す。下の枠とその場の両方に編集画面を開くことはない。

| 種類 | 用途 |
| --- | --- |
| カードエディタ | 主張・証明・ノートを一枚にまとめ、部位タブで切り替える。編集中の数式をプレビューし、`requires` のリンクから依存カードを開ける。 |
| PDF | カードから作った PDF を閲覧し、組版された位置とカードを行き来する。本文は読み取り専用。 |
| テキストエディタ | デッキ設定、プリアンブル、独立した TeX やコードなどの非カードファイルを扱う。対応言語では LSP の定義ジャンプ、参照一覧、診断を表示する。 |

現在位置はデッキ・カード ID・部位、またはファイルパスで識別する。カードは部位ごと、テキストはファイルごとにスクロール・カーソル・選択範囲を記憶する。PDF 側では成果物ごとにページ、スクロール、倍率を記憶する。行き来の途中でも下書きを保持する。

「戻る」「進む」はブラウザーと同じ動作にする。カード↔PDF、`requires`、指摘、定義・参照への実際の移動を一つの履歴に積む。戻った位置から別の場所を開いたら、進む側の履歴を置き換える。単なるスクロールやカーソル移動は履歴を増やさない。過去の位置を再現できない場合は、対象を開ける範囲で復元し、その理由を表示する。

## カードをその場で編集する

カード一覧、読解ページ、指摘台帳のカードリンク、デッキ概要、スレッド内の XML `card-ref` / `finding` に共通の操作を置く。`finding` では指摘先のカードリンクにフォーカスを置いて操作する。選択中またはフォーカス中のカードで `F2` か `Enter` を押すと、その場所で主張・証明・ノートのタブと数式プレビューが開く。Android では長押しメニューの「編集」から開く。

`Ctrl+Enter` で保存し、`Esc` で編集を終了する。未保存の変更があれば、破棄する前に確認する。別のカードを編集しようとした場合も、現在のカードを保存するか破棄するか選んでから切り替える。IME 変換中のキーは入力欄に渡す。

保存には既存のカード編集経路を使い、読み込み時の版を照合する。エージェントなどが同じカードを更新していれば、保存時に競合として返す。編集開始時の内容・最新版・自分の下書きを差分で見られるようにし、解消後は最新版を基点に再保存する。保存内容は変更履歴から取り消せる。複数の部位を変更した場合は、元ファイルごとの版と変更をまとめて扱う。Markdown 一枚に複数の部位がある場合は、一回の更新で反映し、frontmatter や編集対象外の節を保つ。

## カードを作り、デッキの構成を変える

- **作成**。定義（definition）、定理（theorem）、補題（lemma）、命題（proposition）、系（corollary）、例（example）、証明（proof）、解説（exposition）など、デッキが扱う種類に応じたテンプレートを選ぶ。種類の接頭辞と短いスラッグから ID を作る。デッキ内の一意性を保存時にも確認し、衝突したら候補を出し直す。
- **挿入と並べ替え**。`structure.yaml` で、フォーカス中のカードの直後、そのカードの子、章末を選べる。移動・並べ替えも同じ位置指定を使う。子の表現を持たないデッキ形式では、表示と組版で同じ順を読める形に構造の読み書きを拡張する。
- **種類と依存**。公開済みのカード ID を保ったまま、種類と必要な部位を変更する。本文の移し先が変わる場合は保存前に差分を示す。`requires` は検索付きピッカーで追加・解除し、参照切れや循環を検査する。
- **削除**。対象を `requires` で参照するカードを逆引きして一覧を表示する。依存がある場合は警告し、関連カードへのリンクと参照を外す操作を示す。確認後にカードと構成上の項目を取り除き、変更履歴から復元できるようにする。

デスクトップではカードや構成にフォーカスがあるときの「新規カード」に、`Ctrl+N` または `Insert` を割り当てられるようにする。直後への挿入を既定とし、作成したカードをその場編集で開く。Android の長押しメニューには「編集」に加え、「カードを追加」「移動」「種類を変更」「依存を編集」「削除」を置く。

人とエージェントは共通の操作を使う。追加する MCP ツールは `card_create`、`card_move`、`card_delete`、`card_set_requires`。種類変更は既存の本文置換と区別できる形でカード編集経路に加える。カードと構成の読み込み時の版を照合し、変更を一件の履歴にまとめる。途中で保存に失敗した場合は操作前の状態に戻す。作業に書き込みが許されたデッキ内での作成・編集（移動、種類変更、依存編集を含む）は追加承認を求めない。削除は利用者が対象と依存を確認して承認した版だけに適用する。スレッドから依頼した選択範囲の編集は R-12 の差分承認を通す。

## カードと PDF の往復

**PDF → カード。** デスクトップで PDF 上の位置をダブルクリックする。Android では位置をタップする。ページ座標から SyncTeX で TeX の入力ファイルと行を引き、元カードの ID・部位・部位内の行に変換する。同じ枠をカード側に切り替え、クリックした箇所にカーソルを置く。組版枠など部位内の位置を確定できない場合は、得られた粒度でカードまたは部位を開き、その旨を示す。部位内の行は 1 始まりとする。カード外のプリアンブルや独立した TeX 原稿の位置はテキストエディタに渡す。

**カード → PDF。** 主張・証明などの部位で範囲を選ぶかカーソルを置き、切替キーを押す。選択時は範囲の先頭をジャンプの基点とする。必要なら対象デッキをビルドし、カード ID・部位・行に対応する生成 TeX の入力と行を求める。SyncTeX の順引きで同じ枠を PDF に切り替え、対応箇所を短く強調する。対応を取れる範囲は強調し、行が分かる場合は行単位で示す。PDF から同じキーを押すと、直前のカードまたはソースと選択位置に戻る。Android の切替は「PDFを見る」「ソースへ」ボタンを使う。切替キーは変更できるようにし、IME の変換・確定中や OS が予約しているキーと競合しない割り当てを選ぶ。独立した TeX 原稿でも、対象 PDF と対応する入力が分かる場合は同じ切替操作を使える。

### 組版結果と位置情報

- フォルダー型カードでは、組版ルートが元の `statement.tex` や `proof.tex` を `\input` する。カード ID は同じフォルダーの `card.md` で分かり、入力ファイル名と TeX の行から部位と行を引ける。ルート TeX の `% card <id>` / `% end card` はカードを特定する手掛かりになる。
- Writing harness は Markdown の `Statement` / `Proof` や解説本文を `build/cards/` の `*.statement.tex`、`*.proof.tex`、後置きの `*.deferred-proof.tex` などに書き出す。`<成果物名>.sources.json` は生成 TeX の相対パスをキーに、元カード ID・Markdown パス・生成行ごとの元ファイル行を保持する。`synctex.rs` はこの対応を使って逆引きする。証明を別カードが持つ場合、対応表は実際に証明を書いたカードを指す。部位の型は対応表の項目に含まれない。
- 順引きでは、保存済みカードの部位内行を元ファイルの行に変換し、選んだ成果物の対応表から生成 TeX の入力と行を逆に引く。フォルダー型は元の TeX を直接使う。生成時に部位と本文行の対応を明示し、環境の開始・終了行に割り当てられた重複行を本文行と区別する。同じ部位が複数の成果物や箇所に出る場合は対象 PDF を決め、その中の候補を示す。通常のノートなど組版対象外の部位は「PDF に対応する箇所なし」と表示する。
- PDF、SyncTeX とソースマップは同じビルド世代のものを使う。順引きと逆引きの応答には、要求 ID と成果物の版を付ける。画面の移動後に届いた応答でフォーカスを奪わない。ファイルへのジャンプはワークスペース内で解決できる位置に限る。

### ビルドの状態

| 枠の隅の表示 | 切替操作の扱い |
| --- | --- |
| ビルド中 | カード側で完了を待つ。同じ入力版のビルドが進行中なら合流する。成功後、要求がまだ有効なら PDF に切り替える。 |
| ビルド失敗 | カード側に留まり、エラー行へ移動できるようにする。生成 TeX の診断は対応表からカード部位に戻す。行を特定できないエラーではログを開く。 |
| PDF が古い | 初期案では、切替操作で再ビルドを要求して待つ。未保存の変更が組版対象なら、先に保存の確認を出す。前回の PDF は「PDF が古い」と明示して別の閲覧操作から開ける。現行のカード位置との同期は、新しい組版が成功してから使う。 |

保存した入力と出力が対応すると分かる場合は、切替時にビルドを追加せず PDF へ移る。待っている間に対象や入力版が変わった場合は、完了通知を更新しても自動では切り替えない。

## スレッドからの指示と査読

どの種類のエディタでも、選択範囲に一行の指示を添えて上のスレッドへ送れるようにする。カード ID・部位またはファイルパスと、範囲・引用・版を付ける。PDF では選んだ本文とページ位置を渡し、元カードを引ければその位置も添える。スレッドの応答から R-12 の差分を開き、承認時に版を再確認して適用する。PDF から始めた提案の編集先は対応するカードやソースとする。対応が取れない場合も引用を相談に使える。

指摘台帳や XML `finding` のカード／ファイル位置から同じエディタへ移動する。現行版の行はその場所へ進み、過去版の行は版と範囲を表示する。現行版に対応を確認できた場合にだけ現行の行へ移動する。

## 現在の実装と追加するもの

- [`paper.rs`](../../crates/fuzukue/src/paper.rs) は論文順のカード閲覧、数式描画、カードへのスクロールを持つ。[`paper_edit.rs`](../../crates/fuzukue/src/paper_edit.rs) は本文・証明の部位単位のインライン編集を持ち、`SaveCard` / `CardSaveResult` で基点ハッシュと競合を扱う。サーバーの [`cards.rs`](../../crates/secretaire/src/cards.rs) は保存を変更履歴に記録する。[`source/card.rs`](../../crates/fuzukue/src/source/card.rs) には詳細画面のファイル単位編集もある。[`deck_overview.rs`](../../crates/fuzukue/src/deck_overview.rs) の一覧はカード選択の入口になる。これらを共通の編集コンポーネントと保存経路につなぎ、ノートの部位保存と複数部位の更新を加える。
- [`source.rs`](../../crates/fuzukue/src/source.rs) と [`source/lsp.rs`](../../crates/fuzukue/src/source/lsp.rs) はテキスト編集、定義ジャンプ、診断表示を持つ。`SaveSource` / `SourceSaveResult`、`LspBuffer` / `LspDocument`、`LspRequest` / `LspResult` を再利用する。`LspQuery::References` と MCP の `lsp_definition`、`lsp_references`、`lsp_diagnostics` もある。定義・参照の移動先を共通の履歴へつなぐ。
- [`synctex.rs`](../../crates/secretaire/src/synctex.rs) は `pdfinfo` と `synctex edit` を使う。MCP の `locate_pdf` と既存の `LocatePdf` → `Located` は元ファイル・行・カード ID を返す。WebSocket のページは 0 始まりで、MCP は 1 始まり。[`paper_pdf.rs`](../../crates/fuzukue/src/paper_pdf.rs) の成果物ビューはダブルクリックなどで逆引きし、結果からカードの閲覧位置を開く。論文内の PDF 表示では別にカードのポップアップを持つ。
- `GetPaperPdfMap` → `PaperPdfMap` は PDF のダイジェストとカード・証明の領域を運ぶ。行の指定には、[`harness_build.rs`](../../crates/secretaire/src/harness_build.rs) のソースマップと部位内行の変換が別途要る。[`pdf_audit.rs`](../../crates/secretaire/src/pdf_audit.rs) と [`pdf_audit/sync.rs`](../../crates/secretaire/src/pdf_audit/sync.rs) には `synctex view` と `edit` の往復をサンプル検査する実装がある。そこから順引きの処理を再利用し、対話用の順引き要求・応答、ページ座標への変換、短い強調表示を加える。
- [`fuzukue-proto`](../../crates/fuzukue-proto/src/lib.rs) には `BuildPaper` / `CancelBuild` と `BuildStarted` / `BuildStatus` / `BuildResult` がある。`build_paper` と同じデッキ組版を活用する。現状も条件を満たすフォルダー型の論文・本では、保存後に自動ビルドを予約する。切替を特定のビルドに結び付けるため、対象成果物・入力版・出力の世代と、ジャンプ可能なエラー位置をやりとりする。対応クライアントを識別できる形で追加する。
- [`graph/mcp.rs`](../../crates/secretaire/src/graph/mcp.rs) にある `card_read` は読み取り、`card_edit` は主張・証明・ノートなどの一か所置換、`graph_neighbors` は依存の探索に使える。`check_cards` は検査、`create_research` は研究の作成を担当する。カード単位の作成・移動・削除・依存変更を行う専用 MCP ツールは追加が必要。
- [`review_findings.rs`](../../crates/fuzukue/src/review_findings.rs) は指摘台帳のカード・ファイルリンクを持つ。[`chat_components.rs`](../../crates/fuzukue/src/chat_components.rs) の `finding` は表示専用プレビュー。編集操作を追加し、XML の `card-ref` も新しい語彙として定義する。対応しないクライアントでは既存のフォールバックで本文を読めるようにする。

## 未決事項

- `\input` / `\include` を持つ複数ファイルの TeX では、同じ入力を含むルートと成果物の選択規則を決める。
- 手動切替以外でビルドを起動する条件、保存後のまとめ方、増分ビルドで追う依存を決める。古い PDF の判定に含める設定・プリアンブル・外部入力と、長時間の組版で前回版を開く操作を詰める。
- Book harness の `build_paper` が出す全体版と部分版について、対象の既定値、後置き証明や再掲の候補順、生成物一式の保持方法を決める。
- Android の PDF 描画方式と、拡大・回転したページのタップ座標およびテキスト選択の取得方法を検証する。
- PDF 注釈の作成・保存は今回の対象外。

## 実装順

1. スレッド下の単一枠とカードエディタ。三部位・数式プレビュー・依存リンク、版照合付きの保存と変更履歴をつなぐ。
2. 同じエディタをカード一覧・読解ページ・指摘台帳・デッキ概要でその場表示する。続いてスレッドの XML 部品に入口を加える。競合時の差分と保存・破棄を各入口で確かめる。
3. 種類別テンプレートでのカード作成と `structure.yaml` への挿入を追加する。UI と `card_create` を同じ処理につなぎ、作成直後のその場編集までを確かめる。
4. 移動・並べ替え、種類変更、依存ピッカー、依存を確認してからの削除を追加する。UI と MCP を同じ処理につなぎ、版照合・取り消し・削除承認を確かめる。
5. カードから作った PDF を単一枠で開き、ビルド状態とエラー行を出す。フォルダー型と harness 型で部位・行を逆引きし、履歴で移動前に戻れるようにする。
6. 成果物の版をひも付けて、カードからの順引き・短い強調・同じキーでの復帰を追加する。古い PDF や失敗時の操作を確かめる。
7. テキストエディタの定義・参照・診断を履歴とつなぐ。指摘からの位置移動と、各エディタから R-12 に渡す選択範囲を追加する。
8. Android の PDF 描画、位置タップ、切替ボタン、カードの長押しメニューをつなぐ。
