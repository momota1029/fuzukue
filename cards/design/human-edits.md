人がカードや原稿を直したら、その差分を「指示」として扱い、影響を受ける所の整合を取る案を作業役に出させる（従来の設計）。人の編集そのものは書き換えない。

## いつ始めるか

「編集をやめた」と分かる時だけにする。手が止まった時間や、途中の保存では始めない。

- 論文のカード編集（`save_card`）と作業台の編集（`save_file`）は、保存すると画面が閉じる。保存の成功を「閉じた」とみなす。
- ソースエディタは、編集したタブを明示的に閉じた時（`editor_closed`）。タブを開いたまま何度保存しても始めない。
- 利用者が PDF のビルドを押した時（`build_paper`）。そのデッキでたまっている編集を、待たずにまとめて出す。作業役が道具でビルドした時は数えない。

閉じた後は 5 秒待ち、その間に別のカードを閉じたら一つにまとめる。同じデッキの確認が走っている間に次の編集が閉じたら、走っている確認を止めて、前の編集と合わせて出し直す（自動査読の置き換えと同じ）。

## 何を比べるか

利用者の保存が初めてカードに触れた時に、そのカードのファイル（`card.md` と TeX）の保存前の中身を控える。区切りが来たら、控えと今の中身を比べる。控えはデッキごとに持ち、区切りで渡したら空にする。

控えは利用者が保存したカードだけを持つので、同じ時間に作業役が別のカードを直しても人の編集には数えない。同じカードを作業役も直していた場合は区別できず、合わせて人の編集として扱う。控えはサーバーのメモリにあり、サーバーを入れ替えると消える。

## 影響を受ける所の候補

査読役は MCP の道具を持たないので、候補はサーバーが記号の索引（[[symbols]]）から集めて渡す。

- 編集したカードの ID を参照している所（`links`、`requires`、`from`、ウィキリンク）。
- 編集したカードの定義語（`defines`）、`label` と TeX の `\label`、マクロ、`lean:` に挙がる Lean の宣言を使っている所。

候補は同じデッキの中に限り、場所（ファイルと行）と抜粋を付けて最大 40 件。編集したカード自身の、編集していない部分（命題を直した後の証明など）も対象にする。

### 名前の変更と削除

最初の保存前に、カードのファイルとともに記号の索引が拾う名前を控える。確認時に消えた名前を今の索引で探し、同じデッキに残る使用箇所に旧名の印を付け、ほかの候補より先に渡す。同じカードで同じ種類の名前が一つ消えて一つ増えたときは、改名の候補として旧名と新名の組を渡す。それ以外は、消えた名前を列挙する。

## 査読役

査読の種類「整合」（`consistency`、作業役の名前は `review-consistency`）として動かす。置き換え、止める、情報欄の状態の表示、作業役ごとのモデルの上書き、無効化は、ほかの査読と同じ仕組みに載る。既定のモデルは数学査読と同じ。

渡すもの:

- 人の編集: カードごとに、変わったファイルの、消えた行と増えた行（行番号付き）。
- 改名の候補となる旧名と新名の組、および置き換え先が分からない削除名。
- 候補の一覧。
- 前に利用者が断った提案（下の「断った提案」）。

決まり:

- 人の編集は意図した変更として正しいものとみなし、元に戻す・言い換える提案をしない。
- 指摘は、人の編集に合わせて直すべき所だけ。用語を変えた → 使っている所の言い換え。定義の仮定を変えた → それを使う定理・証明・Lean の見直し。記号を変えた → マクロと本文。
- どの編集に合わせるのか、根拠の引用、具体的な直し方を書く。
- ファイルとコメントを編集しない。

## 結果

指摘はコメントの下書きとして、対象のカードに `[人の編集] [整合]` を付けて置く。対象は候補か編集したカードに限り、それ以外のカードへの指摘は捨てる。

- 受け入れる: 下書きを適用する（今のコメントの適用と同じ、別スレッドで直す）。
- 断る: 下書きを消す。
- 一部だけ: 要るものだけを残して適用する。

査読の設定で「下書きを別スレッドで適用する」を選んでいると、整合の提案も自動で適用される（小さく確実なものを自動で当てたい人向けの設定）。

`fuzukue.toml` と `deck.toml` の `[review]` で、`reviewers` に `consistency` を含めない、または `auto = false` にすると、そのデッキでは始めない。既定では含まれる。サーバーを `FUZUKUE_AUTO_REVIEW=0` で起動しても始めない。

## 断った提案

`[人の編集]` の付いた下書きを消すと、その文をデッキの `.fuzukue/rejected-proposals.json` に残す（新しいもの 30 件まで）。次からの整合の確認に「前に断られた提案。同じ趣旨の提案を繰り返さない」として渡す。

## まだやらないこと

- 会話への一行の表示と、押すと差分が開く画面。今は論文の画面の状態の行（「整合確認」）と、コメントの下書きに出る。
- デッキをまたぐ候補。記号の索引はデッキをまたいで引けるが、コメントの下書きがデッキごとなので、まず同じデッキに限る。
- カードの外にある Lean やコードのファイルを直接編集したときの整合確認。
- 方針役の方針がある時に、編集を方針の見直しの材料にすること。
