サーバーが配布用のクライアントを保持し、接続先のクライアントが更新を取得する。クライアントからサーバーを立てたり、別の端末にクライアントを渡したりする構成も検討する。

## 自動更新

- **置き場**: サーバーの状態フォルダに `builds/<platform>/` を置き、クライアントの実行ファイル、版（git のコミットと日時）、SHA-256 を持つ。`<platform>` は `windows-x86_64`、`linux-x86_64`、`macos-aarch64`。
- **入れる**: `secretaire publish-client <platform> <file>` で置く。手元の WSL からは、Windows 側でビルドして置くスクリプト `scripts/publish-windows.sh` を用意する（今の手順を一本にしたもの）。サーバーの画面からの「クライアントを作る」は次の段。
- **配る**: HTTP の `/client/<platform>` と `/client/<platform>/manifest`。認証は WebSocket と同じ（ループバック、Tailscale の許可リスト、トークン）。WebSocket の `Welcome` に、その端末向けの最新の版を載せる。
- **更新する**: 自分より新しい版があれば、情報欄に「更新があります」と出す。押すと取ってきて SHA-256 を確かめ、自分を入れ替えて再起動する。Windows では動いている exe を `.old` に改名してから新しいものを置く。一つ前の版は残し、起動に失敗したら戻せる。設定で「自動で入れ替える」も選べる（既定は確認してから）。
- プロトコルの版が合わなくて接続を断られた時も、更新だけはできるようにする（HTTP の経路なので WebSocket の版に縛られない）。

## クライアントがサーバーを兼ねる

今もクライアントは WSL やローカルのサーバーを起動できる（[[windows-launch]]）。これを「この PC をサーバーにする」の設定として表に出す。

- 起動したサーバーを、手元だけでなく Tailscale の IP でも待ち受けさせる（[[remote-access]] の `listen` と許可リスト）。
- 設定の画面に、他の端末からつなぐ URL と、Tailscale でつなげる端末の一覧（`tailscale status --json`）を出す。Android 用に QR コードも出す。
- クライアントを閉じてもサーバーを残すか（他の端末が使っている時）を選べる。

## 送る

- 「端末に送る」: Tailscale の端末を選んで、その端末向けのクライアントを渡す。相手にクライアントがあれば、相手は自動更新で取りに来るので、送るのは「更新があります」の知らせだけ。相手にまだない時は、`tailscale file cp` で実行ファイルと、つなぎ先を書いた設定ファイルを送る。
- 相手がオフラインの時は、送る予定として残し、相手がオンラインになったら送る（Tailscale の状態を見て再試行）。

## 安全

- 配る実行ファイルは、置いた時の SHA-256 で確かめる。署名は次の段（配る範囲が自分の端末から広がる時）。
- 更新の取得も、WebSocket と同じ認証を通す。トークンなしで外から取れないようにする。

## 実装メモ

- プロトコル 28 で `Hello` の端末情報、`Welcome` の配布情報、更新通知を追加した。配布 HTTP 経路は WebSocket のプロトコル番号に依存しない。
- ビルドの登録、配信、クライアントの更新と接続確認による巻き戻し、Tailscale でのサーバー公開と送信を実装した。操作手順は [docs/update.md](../../docs/update.md) にまとめた。
- サーバーは接続元の Tailscale IP を記録する。送信待ちは送信元のクライアント設定に保存し、起動中に端末一覧を確認して再試行する。
- オフライン環境に QR コード用クレートがなかったため、Android にはコピーできる接続 URL を使う。
