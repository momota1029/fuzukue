> 「いや，執筆のときに新しく書いたカードに対して文体査読とかいれるんですよ．正直人間が文章を書くよりもポン出しした論文のクオリティが高いほうが望ましいと思います．」

## 対象

相談役の作業ディレクトリで `deck.toml` を探す。入力を相談役に渡す直前と、
ターンの終了後に、ローカルの `Graph` が認識した Markdown と
付属 TeX のパス・内容をカード ID ごとに比較する。
新規カードや新規デッキ、シェル経由の編集、残っているカードの TeX の削除も拾える。
ターンの間に別の会話や外部エディタが同じデッキを書き換えた場合も差分に含まれる。

用語 lint は変更カードの本文を検査する。用語の定義・依存・掲載順には
デッキ全体の情報を使う。Lean 査読は変更カードのうち
`lean:` のあるカードだけを対象にする。Lean と数学の査読は読み取り専用の Codex スレッドで実行し、
一覧外のカードへの指摘は除外する。

### 実装

> 「文体査読は全体を通すんじゃなくて編集したところだけにするべきです」

変更前の原文を保持し、行差分で得た追加・変更行を段落単位に広げる。自動文体 lint
はその範囲に重なる診断を返す。Claude の文章査読には範囲と前後の行を元ファイルの行番号付きで
渡し、範囲外の指摘を除外する。新規カードは本文全体が対象で、削除だけの差分には
指摘を出さない。明示的な全体査読と lint は従来どおり実行できる。

## フィードバック

デッキごとに約 5 秒間、変更カードをまとめる。文章、Lean、数学を並行に実行し、
同じデッキと役割の査読が進行していれば中断して新しい変更を取り込む。
相談役のターンは独立して進む。使用量の上限に達したバックエンドの査読は見送る。

指摘は `[自動査読]` を付けて `.fuzukue/comments.json` の下書きに追記する。
既定では今のスレッドに送る（2026-11-20、ユーザー:「カード集へのコメントはメインスレッドに送っても問題なさそうなので，そっちをデフォルトに」）。送信ボタン横の▼で「別スレッドで反映」を選ぶと、今回追加した下書きからコメント反映用の会話を作る。
自動反映からの再査読は行わない。

## 設定

自動査読は既定でオフ。使うときは `fuzukue.toml` か `deck.toml` の `[review]` に `auto = true` を書く。
プロジェクト直下の `fuzukue.toml` に置いた設定は、`deck.toml` の同じキーで上書きできる。
`FUZUKUE_AUTO_REVIEW=0` で全体を無効化する。

```toml
[review]
auto = true
reviewers = ["style", "lean", "math", "consistency"]
lints = true
```

モデル、思考レベルと指摘の扱いはワークスペース設定の「査読の相手」で変更できる。
`consistency` は人の編集を閉じた時の[[human-edits|整合確認]]に使う。

## これから

カードが変わったら、サーバーは受付の次のターンに、デッキ・カード ID・変更量・使える査読の種類を短いメモで添える。受付はそのメモを見て、`request_review` を呼ぶか決める。この通知はまだ未実装。
