## 決定（2026-11-25、ユーザー）

指示と資料を明示してモデルを一回だけ呼び、本文と使用量を受け取る共通関数を作る。モデルに道具を公開せず、作業ディレクトリを空にし、渡した資料だけで答えさせる。節のブラインド査読から取り出し、査読、本の節の下書き、モデル名を伏せた比較で使う。要約やスレッド題名にも後から使えるようにする。

友人が使う入口は、論文と同じようにカードで管理している既存の本のデッキ。カードを正本とし、節はデッキの構造上の単位で選ぶ。「この節の下書きを作って」と話すと、一節の本文案をカードの差分で見られる。LaTeX 原稿だけがある場合は、既存の取り込みを経て同じデッキの入口へ進む。

## 現行の実装から取り出す

- 節のブラインド査読は、節と対象の掲載順を読み、依存と明示した許可表から抜粋を作る。指示と抜粋を合わせた `packet.message`、指紋、送信試行を記録してから、汎用のブラインド委譲と共有する `Connection::complete` を呼ぶ。返答本文のほか、提供元の応答、確定モデル、確認範囲と所見を節査読側に保存する。共有しているのは直接 API の通信で、通常の査読セッションの `ReviewLease` はこの経路で発行しない。 [節と資料の選択](../../crates/secretaire/src/reviewers/section/blind/sources.rs#L198) · [査読の実行](../../crates/secretaire/src/reviewers/section/blind.rs#L396) · [査読の設計](review-workflow.md)
- `delegate/blind.rs` のモデル指定・認証確認、リクエストの構築、応答の読み取り、使用量の取得を共通関数の起点とする。現行の OpenAI Responses と Anthropic Messages はどちらもユーザーメッセージ一件と `tools: []` を送り、OpenAI は `store: false` も指定する。初段は両呼び出し元を移し、既存の送信本文・リクエスト形状と、拒否・打ち切り・確認範囲の扱いを既存の試験で照合する。査読の許可表、判定、採否、台帳は査読側が持つ。 [直接 API の実装](../../crates/secretaire/src/delegate/blind.rs#L108) · [現行の送信本文を調べる試験](../../crates/secretaire/src/integration_tests/section_math_blind.rs#L296)
- 通常の Claude は `claude -p` の stream-json に MCP と追記指示を付ける。通常の Codex は app-server のスレッドに開発者指示や MCP を設定できる。CLI を足す段階ではストリームの解釈と使用量の取得を流用し、隔離用の起動は独立に構成する。 [Claude の起動](../../crates/secretaire/src/claude.rs#L168) · [Codex の起動](../../crates/secretaire/src/codex.rs#L423)

## 共通関数の契約

- 呼び出し元は実行経路（Claude Code、Codex app-server、Anthropic Messages、OpenAI Responses）、その経路のモデル ID、指示、順序付きの資料本文を指定する。資料は呼び出し元がワークスペース権限で解決した UTF-8 の値として渡す。資料内に書かれた命令・パス・URL は資料の一部として扱う。共通関数にはパスを開く操作を持たせない。返す値は本文、入出力・キャッシュ・推論など提供元が報告した使用量、実際のモデル、実行記録 ID。未知の値とゼロを区別し、購読枠と API の使用量は実行経路とともに表示する。
- CLI は毎回新しい空の作業ディレクトリと新規セッションを使う。管理された認証経路と隔離用設定だけを持たせ、原稿・作業ツリー・履歴・プロジェクトや利用者の指示・メモリ・プラグイン・スキル・フック・MCP を継承しない。必要な設定ファイルは作業ディレクトリの外に置く。直接 API はエージェントプロセスを起動せず、作業ディレクトリやファイルを渡さない。どの経路でもシェル、ファイル読み書き、検索、Web、エージェント委譲を含め、モデルに公開されるツール集合は空とする。許可拒否や読み取り専用の設定だけでは条件を満たさない。
- モデル呼び出し前に、送信する指示・資料の全文、順序と役割、実際に組み立てたリクエスト本文（CLI ではモデル入力、起動引数と設定のうち秘密を含まない有効値）、モデル指定、出力上限などの実行条件とアダプター・CLI の版を、ワークスペースごとの非公開サーバー状態に固定する。認証ヘッダー・鍵・トークンは記録せず、一般ログには実行 ID と状態を出す。保存に失敗したら送らない。結果、使用量、実モデル、失敗・中断、送信を試したかを同じ ID に結び付ける。再実行は原稿やパックを読み直さず、保存済み入力を同じ経路へ渡す。版や隔離条件を再現できないときは理由を出して止める。同一のモデル出力までは保証しない。
- CLI の購読利用は本人の契約・サインインで使う経路。API はサーバーの API 鍵を明示して使う従量経路。CLI でも認証モードや追加利用によって課金先が変わりうるので、有効な認証・利用枠を確認し、課金先を確定できない設定で自動実行しない。実行前に経路と課金先を示す。未対応の版、認証・隔離の不成立、指定モデルが使えない場合、タイムアウト、拒否、打ち切りやツール呼び出しの検出は状態と理由を返す。通常エージェント、別モデル、別の課金経路への自動切り替えは設けない。 [Claude Code の認証と利用条件](https://code.claude.com/docs/en/legal-and-compliance) · [Codex app-server の ChatGPT プラン接続](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server)

### システム指示と隔離の確認範囲

既定のシステム指示とはクライアントが組み立てる指示を指す。提供元内部の指示や制約は置換・観測の対象外。以下は 2026-11-25 に確認した範囲。

| 経路 | 指示の置き場所と確認状況 | 道具なしの確認 |
| --- | --- | --- |
| Claude Code `claude -p` / stream-json | 公式 CLI リファレンスでは `--system-prompt` / `--system-prompt-file` が既定プロンプトを置換し、`--append-system-prompt` は追記する。実機での置換結果は未確認。 [CLI リファレンス](https://code.claude.com/docs/en/cli-reference#system-prompt-flags) | 組み込みは `--tools ""`、MCP は空の厳格な設定と拒否規則、設定の自動探索も抑える候補を実機で合わせて試す。`--bare` 単独では組み込みツールがあり、管理者設定も検査対象。サインインと併用できる構成、実効ツール集合が空であることは未確認。 [CLI の引数](https://code.claude.com/docs/en/cli-reference) |
| Codex app-server | 手元の `codex-cli 0.169.0` が生成する `ThreadStartParams` に `baseInstructions` と `developerInstructions`、起動応答に `instructionSources` がある。公式設定には組み込み指示を置換する `model_instructions_file` がある。`baseInstructions` が実リクエストで置換する範囲や他の自動挿入は未確認。追記の開発者指示だけで置換済みとは扱わない。 [プロトコル定義](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/ThreadStartParams.ts) · [設定リファレンス](https://learn.chatgpt.com/docs/config-file/config-reference) | 新規の一時スレッド、空の runtime 環境、MCP・動的ツールの無効化、シェル等の組み込み機能を止める設定を検査する。空の `dynamicTools` は組み込みツールの無効化を示さない。送信先での組み込みを含む実効ツール集合が空であることは未確認。 [app-server](https://learn.chatgpt.com/docs/app-server#start-or-resume-a-thread) |
| Anthropic Messages API | リクエストの `system` にシステム指示を置けることを公式仕様で確認した。既存の査読入力はユーザーメッセージ一件のまま移行し、新規呼び出しで指示と資料を分ける。実 API で新しい形の動作は未確認。 [Messages API](https://platform.claude.com/docs/en/build-with-claude/working-with-messages) | `tools: []` と単発のメッセージを現行のフィクスチャが照合する。ツールを要求する異常応答も失敗にする。 |
| OpenAI Responses API | リクエストの `instructions` で system または developer の指示を渡せることを公式仕様で確認した。既存の査読入力はユーザーメッセージ一件のまま移行し、新規呼び出しで指示と資料を分ける。実 API で新しい形の動作は未確認。 [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create) | `tools: []`、`store: false`、ユーザーメッセージ一件を現行のフィクスチャが照合する。会話 ID や前回応答 ID を渡さず、ツールを要求する異常応答は失敗にする。 |

バックエンドごとに、実際の送信内容または実効ツール登録を捕捉し、空であることをテストする。CLI は模擬ストリームでの単体試験に加え、配布対象の実バイナリで確認する。空の作業ディレクトリの外に置いた検出用のファイル・指示、親側のダミー MCP・フック、組み込みツールを使わせる合成入力を用意する。既定指示の置換と追加の指示の有無も、観測できる入力で確認する。モデルの「道具はない」という返答や、呼び出しが観測されなかったことだけでは合格にしない。版が変わったら再検証し、実効ツールの空集合や許可資料だけの入力を確認できない CLI は隔離経路として有効にしない。

## 既存デッキで一節を書く

1. **対象を選ぶ。** 開いているデッキと節を `DeckConfig` と既存の構造の読み取りから解決し、同じ節にある編集対象のカードと部位を固定する。初段は一節の既存の説明カード一枚（必要なら著者が先に置いた空カード）の本文。Markdown の本文またはフォルダー形式の `statement.tex` を既存の形式のまま使う。節全体の構想は入力にする。複数カードへの配分、カード作成、節順序の変更は初段の外に置く。 [節の読み取り](../../crates/fuzukue-cards/src/course.rs#L488) · [カードの編集部位](../../crates/secretaire/src/cards.rs#L282)
2. **渡すものを固定する。** 節のアウトラインと対象読者、許可する定義・結果・記法の抜粋、前節までの短い要約、文体規則を入力とする。依存辺をたどって先に使えるカードを選び、`definition` の候補と有効なマクロ設定から必要な記号を確かめる。節順、カード ID、版、引用元、優先順、サイズ上限をサーバーで管理する。候補の検索結果だけで前提を採用しない。先取り、循環、曖昧な記号、欠けた必須の前提は対象を示して解消を待つ。要約は最初は著者が指定・確認した短文を使い、資料の追加や欠落を黙って補わない。改稿時にモデルへ現行本文も見せるなら、同じ明示資料として固定する。 [グラフの入口](../../crates/secretaire/src/graph/mcp.rs#L37) · [記号索引](../../crates/secretaire/src/graph/symbols.rs#L629) · [マクロの取り出し](../../crates/secretaire/src/cards.rs#L141)
3. **本文を書き、別に確かめる。** 共通関数には本文だけを要求する。パス、カード ID の変更、編集命令、差分、作業メモをモデルに出させず、対象カードへの差分は Rust 側で組み立てる。空出力、途中打ち切り、対象部位に合わない形はその場で失敗を示す。差分を正本に書かずに、明示された用語の先出し・依存漏れ、用語揺れ、未解決参照、許可集合にない外部記号や TeX マクロを検査する。既存の `check_cards` 相当の検査と用語・文体の設定を候補版・隣接カードに再利用する。本文部位から外れる設定変更や外部ファイルの読み込み命令を候補から弾き、下見で候補の TeX を自動実行しない。本文中で導入する局所変数と外部記号を区別し、解析で判断できない箇所は未確認とする。数式の意味、仮定、量化、既知の結果の適用は、候補版・必要な前提・確認指示だけを渡す別の隔離呼び出しで確認する。執筆時の会話、自己評価や先行する査読結果は渡さない。既存の節査読の所見・確認範囲の形式を使い、候補の位置と版に結び付ける。 [カード検査](../../crates/secretaire/src/mcp.rs#L2274) · [用語検査](../../crates/fuzukue-cards/src/term_lint.rs#L175) · [版の照合](../../crates/secretaire/src/reviewers/section/blind.rs#L490)
4. **同じ会話で採否を決める。** 「第 2 節を書いて」「この用語で書き直して」「この差分を採用」で進める。対象、完全なカード差分、機械検査と数学確認の所見・未確認範囲を一件で示す。未確認ならその状態を示し、著者は保留、再試行、破棄を選べる。採用は表示した候補版にひも付き、入力の版と正本を再照合してから既存のカード保存経路で一度だけ反映する。対象や参照前提が変わったら差分と確認を取り直す。`card_edit` は書いた後に検査を返すため、部位の決定・置換・保存前照合と検査を再利用し、下見用の候補に適用する。 [差分と変更後の検査](../../crates/secretaire/src/graph/card_tools.rs#L215) · [カード保存時の版照合](../../crates/secretaire/src/cards.rs#L390)

一節に複数のカードがある場合は、アウトラインの項目を既存の節内カードと部位に割り当て、順に本文を起こす。同じ提案内の先行カードを使う場合も、その候補本文は版を付けた明示資料とする。機械検査と数学確認は一節の候補版を対象とし、カードごとの本文差分と所見を一件で見せる。採用時は全対象と依存の版を先に照合し、中断からの復旧を含めて一つの節の変更として確定する。

LaTeX 原稿から始める場合は `import_latex_book` を使う。既存の Rust 実装が `\\input` / `\\include` を展開し、新規のデッキに `structure.yaml`、`preamble.tex`、`card.md`、`statement.tex` と該当する `proof.tex` を作り、ラベルと出典行を残す。最初は原稿を正本とするミラー。取り込み報告の PDF 抽出本文・AUX・参照警告と `reading_sync_check` の原稿行範囲・ファイル照合を確認し、著者が元原稿の編集を止めてカードへ切り替えた後に差分を採用できる。比較を省略した場合は未検証、再取り込みは別デッキへの新規作成と扱う。 [取り込みの実装](../../crates/fuzukue-cards/src/latex_book.rs#L841) · [取り込みと切り替え](../../docs/book-harness.md#移行の段階)

## 規則を置く場所

同梱の `book-harness` と本のひな形、手元で読める labo-skills の `book-harness`（`migration.md`、`pool-and-route.md`、`check-codes.md`、`writing-rules.md`）、`reading-book`、`course-authoring`、`reading-book-math-review`、`math-verifier` を参照した。上流の `book` は共有の事実カードと本ごとの並びを操作するコマンド群。上流の共有プール、A1–A6、C2 台帳や CLI を、既存デッキで一節を書くための前提に置かない。 [同梱スキル](../../skills/book-harness/SKILL.md) · [本のひな形](../../templates/book/AGENTS.md) · [上流との形式の対応](../../docs/book-harness.md#labo-skills-の-book-harness-との対応)

| 出どころと決まり | Rust が扱うこと | 編集できる規則・著者の判断 |
| --- | --- | --- |
| `book-harness` の正本、安定 ID、掲載順、依存、指紋、ミラーと切り替え | 節・対象部位・前提の照合、パックの固定、順序・参照・循環・版の検査、差分採用と競合防止。インポートの報告と原稿の同期状態も利用する。 | どの前提を既知とするか、同じ結果を再利用するか仮定の違う別の結果とするか、原稿からいつ切り替えるか。 |
| `writing-rules.md`、`reading-book`、`course-authoring` の執筆作法 | 既存のデッキ・パック設定から表記辞書、除外語、句読点など判定可能なルールを読み、検査位置を返す。 | 言語、文体、想定読者、章の問いと到達点、動機・例の置き方、何を冒頭で導入するか、どこまで証明を詳述するか、資料の採用範囲。 |
| `reading-book-math-review` と `math-verifier` の独立確認 | 固定した候補と許可資料を別の実行へ渡し、所見の位置、対象版、確認範囲と不足を記録する。 | 仮定・量化・境界例・論証をどの深さで確かめるか。所見をどう直すか、採用するかは著者が決める。 |

文体・用語の設定は既存の `[[rules]]` のレイヤー順とデッキ側の上書きを使う。同梱の見本と規則の解決処理を確認した。友人のデッキで選ばれたパックと上書きは、利用時にそのデッキで解決する。文章で書く作法と数学確認の観点は、利用者が選んだ規則パックの版から、必要なテキストだけを読み取って入力へ固定する。パックのスキルや付属スクリプトをモデル実行時に読み込ませない。公開リポジトリに置くのは設計・汎用の規則・合成試験資料。未公開の原稿、原著や抜粋、依存カード、執筆・査読結果、再実行記録は公開物に入れない。先に資料ごとの利用条件を確かめ、機外送信が禁じられた原著・カード・規則は購読 CLI にも API にも送らない。その場合は対象と不足を示して止める。 [規則パック](rule-packs.md#実装)

## モデルの役割と比較

構成・定義の検討と数学確認には大きいモデル、固定したアウトラインからの本文起こしには小さいモデルで足りる、という案は未検証。役割ごとにバックエンド・モデル・設定・予算を選べるようにし、定義や記法の確定は著者が行う。初段は執筆と数学確認の二役を個別に指定できればよい。

比較では、一つの固定入力を明示した複数モデルへそれぞれ独立に渡す。候補名と順序を無作為化し、評価が済むまでモデル・経路・使用量を評価者に伏せる。評価者には同じ資料と採点基準を渡し、用語・記法の診断、数学上の欠落、説明の明瞭さ、著者が直した量を残す。評価後に対応表、失敗件数、入力・出力の使用量、時間と課金経路を開示する。経路間でシステム指示の扱いや設定が違う場合は、実行条件の差も記録する。別モデル一回の印象で役割の既定を変えない。

## 実装の順序と完了条件

実装は進行中の [R-91](../../roadmap/cards/R-91.md) が終わってから始める。

1. [R-94](../../roadmap/cards/R-94.md) で既存のブラインド査読から直接 API の共通関数を抽出する。現在の査読・委譲が同じ入力で動き、新しい呼び出し元が本文と使用量を得て、実送信相当の内容を再実行できることが最初の成果。
2. [R-95](../../roadmap/cards/R-95.md) で友人が使う最小の執筆経路を通す。既存デッキの一節から本文案を作り、検査と独立の数学確認を付け、採用した差分だけを書ける。初段は利用者が選び有効にした直接 API で動く。購読枠のみで使うには、対応する CLI が [R-96](../../roadmap/cards/R-96.md) の条件を満たす必要がある。
3. [R-96](../../roadmap/cards/R-96.md) で CLI を個別に検証して追加する。依存は R-94。隔離が立証できた経路だけ有効にする。
4. [R-97](../../roadmap/cards/R-97.md) で固定した節入力のブラインド比較を通す。直接 API でも比較でき、CLI は検証済みのものを選べる。要約・スレッド題名への接続は、同じ関数に明示入力を渡す後続の用途とする。
5. [R-98](../../roadmap/cards/R-98.md) で一節の複数カードをまとめた差分まで扱う。依存は R-95。

[R-19](../../roadmap/cards/R-19.md) は labo ワークスペースで査読を始めるときに実 API 鍵と既定の査読先を確認する保留事項。R-94 の模擬試験や R-95 の明示設定に必須の前提にはしない。
